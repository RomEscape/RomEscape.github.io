## 연구 질문

| 순서 | 내용 |
|---|---|
| 본 현상 | Middleflow는 CODI보다 추론 23%, 학습 21% 빨랐고 Latent 없음은 41%, 36% 빨랐습니다. 지금까지 비용은 시간으로만 적었습니다. 11월 25일 회의에서 "비용을 FLOPs로 세야 Latent 없음의 이점이 더 잘 보일 것"이라는 의견이 있었습니다. |
| 든 의문 | latent의 비용은 계산량에서 오는가, 시간에서 오는가? FLOPs로 세면 세 모델의 차이는 어떻게 보이는가? |
| 그때까지 안 해 본 것 | 모델별 FLOPs를 실제 토큰 길이로 센 적이 없었습니다. |
| 그래서 한 것 | 학습 자료 383,820개와 GSM8K 1,319문항의 실제 토큰 길이로 학습과 추론의 FLOPs를 셌고, 식은 PyTorch의 FLOP 카운터로 확인했습니다. 그리고 잰 시간과 견줬습니다. |
| 답 | FLOPs 차이는 2~8%, 시간 차이는 21~41%였습니다. 시간은 "latent 계산에서 차례로 지나는 layer 수"에 거의 정확히 비례했습니다(결정계수 추론 0.992, 학습 0.996). |
| 다음 의문 | 같은 학습 시간과 같은 FLOPs는 전혀 다른 기준입니다. FLOPs로 맞추면 Middleflow가 더 학습할 수 있는 양은 2.7%뿐이고 시간으로 맞추면 27%입니다. 지금 하는 [학습 시간 맞춤](2026-11-24-mf-m-llama-codi-time.html)은 시간 기준입니다. |

질문의 사슬 전체는 [연구 질문으로 다시 쓴 Middleflow 연구](2026-11-25-mf-o-research-questions.html)에 있습니다.

## 한 줄 요약

- 실제 토큰 길이로 FLOPs를 세면, GSM8K 한 문항을 풀 때 CODI는 163.0 GFLOPs, Middleflow는 155.8(4.4% 적음), Latent 없음은 150.1(7.9% 적음)입니다. 학습 한 예는 576.4, 561.3(2.6% 적음), 549.3 GFLOPs(4.7% 적음)입니다.
- 그런데 실제 시간은 Middleflow가 추론 23%, 학습 21%, Latent 없음이 41%, 36% 짧습니다.
- 시간은 latent 계산에서 차례로 지나는 layer 수에 비례합니다. 추론은 75.2 ms + 0.53 ms × (layer 수), 학습은 12.2시간 + 0.070시간 × (layer 수)로 여섯 모델이 거의 한 직선에 놓입니다.
- latent는 앞 latent의 결과가 나와야 다음을 계산할 수 있어, 계산량은 작아도 GPU가 차례로 기다리는 시간이 깁니다. Middleflow가 줄인 것은 FLOPs가 아니라 이 차례 수(96 → 42)입니다.

## 왜 궁금했나

Middleflow의 이점을 말할 때 "latent 계산 56% 감소"와 "추론 23% 감소"를 함께 적었습니다. 두 숫자가 다른데, 어느 쪽이 비용인지 정한 적이 없었습니다. 비용을 FLOPs로 세는 것은 하드웨어와 상관없는 기준이라 논문에서 흔히 쓰입니다. FLOPs로 세면 세 모델의 차이가 시간과 같은 순서, 같은 크기로 보이는지 확인했습니다.

## 용어 풀이

| 용어 | 뜻 | 이 글에서의 값 |
|---|---|---|
| FLOPs | 곱셈과 덧셈의 횟수. 곱셈 한 번 + 덧셈 한 번을 2로 센다 | 토큰 하나가 Llama layer 하나를 지날 때 원래 가중치만 121.6 MFLOPs(1억 2,160만 번) |
| GFLOPs | FLOPs 10억 단위 | GSM8K 한 문항, CODI 163.0 GFLOPs |
| LoRA 몫 | 학습한 작은 덧붙임 가중치(LoRA, r=128)의 계산 | 토큰 하나, layer 하나에 11.3 MFLOPs(원래 가중치의 9%) |
| attention 몫 | 앞 토큰들을 읽는 계산. 문맥이 길수록 커진다 | 토큰 하나, layer 하나에 4 × 2,048 × (문맥 길이) |
| LM head | 내부 표현을 다음 토큰 확률로 바꾸는 마지막 계산 | 토큰 하나에 525.3 MFLOPs. 답 토큰을 고르는 자리에서만 센다 |
| 정방향, 역전파 | 학습은 답을 계산하는 정방향과 기울기를 계산하는 역전파로 이루어진다 | 고정된 원래 가중치는 역전파에서 입력 쪽 기울기만(정방향의 1배), LoRA와 attention은 2배 |
| 한꺼번에 계산 | 질문처럼 이미 주어진 토큰들은 GPU가 동시에 계산한다 | 828번 문항의 질문 41토큰을 한 번에 |
| 차례로 계산 | latent와 답 토큰은 앞의 결과가 나와야 계산할 수 있어 하나씩 계산한다 | CODI는 latent 6번 + 답 8번 |
| 차례로 지나는 layer 수 | latent 계산에서 하나씩 차례로 지나야 하는 layer의 수. latent 하나가 지나는 layer 수 × latent 수 | CODI 96, Middleflow 42, Latent 없음 0 |
| 결정계수 R² | 직선이 점들을 얼마나 잘 설명하는지. 1이면 모든 점이 직선 위 | 추론 0.992, 학습 0.996 |

## 방법

1. **세는 것.** 행렬곱만 셉니다. 정규화, 활성 함수, softmax는 뺍니다(합쳐 1% 안팎). 묶음 채우기(padding)로 생기는 낭비도 세지 않습니다. 그래서 이 값은 "모델이 꼭 해야 하는 계산량"입니다.
2. **토큰 길이.** 학습 자료는 GSM8K-Aug를 학습 코드와 같은 규칙(질문+풀이+답이 200토큰 넘으면 뺌, 답이 숫자로 시작하지 않으면 뺌)으로 거른 383,820개입니다(학습 step 수 × 묶음 크기 / epoch = 383,872와 거의 같음). 평균 길이는 질문 45.2, 풀이 12.4, 답 6.3토큰입니다. 시험은 GSM8K 1,319문항(평균 질문 59.3, 답 6.1토큰)입니다.
3. **학습 한 예.** 교사 쪽(질문+풀이+답, 모든 layer, 풀이와 답 자리의 LM head)과 학생 쪽(질문, latent 6 step, 답)의 정방향과 역전파를 더합니다.
4. **추론 한 문항.** 질문 읽기(질문 + bot, 모든 layer), latent 6 step(latent가 지나는 layer만), 답 쓰기(eot + 답 + 끝 토큰, 모든 layer와 LM head)를 더합니다.
5. **식 확인.** 같은 구조의 작은 모델(layer 2개, 무작위 가중치, LoRA r=128)을 PyTorch의 FLOP 카운터로 돌려 식과 견줬습니다. 정방향은 Llama, GPT-2 모두 식과 정확히 같았고(비율 1.000), 역전파는 식이 2~3% 많게 셌습니다(0.983, 0.968). 첫 layer 입력 쪽 기울기처럼 실제로는 계산하지 않는 몫까지 셌기 때문입니다.
6. **시간.** 같은 GPU에서 잰 기존 값을 씁니다(추론은 GSM8K 문항당 평균, 학습은 10 epoch).

## 실험 예시: GSM8K 828번 문항으로 따라가 보기

**문항.** Mulan has $40. Her father gave her $100. She buys two pairs of jeans at $30 each and a bag for $20. How much money does Mulan have left? (정답 60)

Llama tokenizer로 질문은 40토큰(시작 토큰 포함), 여기에 bot 토큰을 붙여 41토큰입니다. 답 "The answer is: 60"은 6토큰이고, 답 쪽에서는 eot와 끝 토큰을 합쳐 8번 차례로 계산합니다.

| 단계 | 토큰 | 지나는 layer | CODI | Middleflow | Latent 없음 | 계산 방식 |
|---|---:|---|---:|---:|---:|---|
| 질문 읽기 | 41 | 16개 | 87.3 G | 87.3 G | 87.3 G | 한꺼번에 1번 |
| latent 6 step | 6 | CODI 16개, Middleflow 7개 | 12.89 G | 5.70 G | 0 | 차례로 6번 (Latent 없음 0번) |
| 답 쓰기 | 8 | 16개 + LM head | 21.27 G | 21.27 G | 21.26 G | 차례로 8번 |
| **합** | | | **121.5 G** | **114.3 G (94.1%)** | **108.6 G (89.4%)** | |
| 차례로 지나는 layer 수 | | | 16 + 96 + 128 = **240** | 16 + 42 + 128 = **186 (77.5%)** | 16 + 0 + 128 = **144 (60.0%)** | 질문 읽기는 한 번으로 셈 |

**읽는 법.** FLOPs의 대부분(72%)은 질문 41토큰을 읽는 데 듭니다. latent 몫은 CODI에서도 11%입니다. 그런데 GPU는 질문 41토큰을 한꺼번에 계산하므로, 이 문항에서 시간을 정하는 것은 차례로 하는 계산입니다. 차례로 지나는 layer 수의 비율(Middleflow 77.5%, Latent 없음 60.0%)이 아래 표의 실제 시간 비율(76.9%, 58.6%)과 거의 같습니다.

## 그래서 무슨 뜻인가

- **FLOPs로 보면 latent 계산은 전체의 작은 몫입니다.** CODI에서도 추론 계산의 7.9%, 학습 계산의 4.7%입니다. 계산의 대부분은 질문을 읽고 답을 쓰는 데 듭니다.
- **시간으로 보면 큰 몫입니다.** latent는 앞 latent의 결과가 나와야 다음을 계산할 수 있어, GPU가 토큰 하나짜리 계산을 차례로 6번 기다립니다. 토큰 하나짜리 계산은 GPU를 거의 채우지 못하므로, 계산량이 작아도 한 번에 드는 시간은 답 토큰 하나를 쓰는 시간과 비슷합니다. 그래서 시간은 FLOPs가 아니라 차례로 지나는 layer 수를 따라갑니다.
- **Middleflow가 줄인 것은 이 차례 수입니다.** 96에서 42로 줄였고, 시간이 그만큼 줄었습니다. 같은 수(48)인 latent 3개 CODI와 시간이 같은 것도 같은 이유입니다.
- **회의에서 나온 예상과는 반대였습니다.** 전체 FLOPs로는 Latent 없음이 CODI보다 7.9% 적을 뿐이고, 시간으로는 41% 적습니다. latent 몫만 떼어 보면 0 대 12.9 GFLOPs로 분명합니다. 발표에서는 세 기준(전체 FLOPs, latent 몫 FLOPs, 실제 시간)을 함께 보입니다.
- **비교 기준이 결론을 바꿀 수 있습니다.** 같은 학습 시간으로 맞추면 Middleflow는 CODI보다 27% 더(12.73 epoch), Latent 없음은 55% 더(15.52 epoch) 학습합니다. 같은 FLOPs로 맞추면 2.7%(10.27 epoch), 4.9%(10.49 epoch)만 더 학습합니다. [학습 시간 맞춤](2026-11-24-mf-m-llama-codi-time.html)의 결과는 "같은 GPU 시간"을 줬을 때의 결과로 읽어야 합니다.

## 한계

- 행렬곱만 셌습니다. 정규화, softmax 등을 더하면 1% 안팎 늘어납니다.
- 묶음 채우기(padding)로 생기는 낭비를 세지 않아, 실제 GPU가 한 계산은 이보다 큽니다.
- 시간과 layer 수의 직선 관계는 이 GPU와 이 묶음 크기(학습 32, 추론 128)에서의 관계입니다. 묶음이 커서 GPU를 꽉 채우면 FLOPs 쪽에 가까워질 수 있습니다.
- 여섯 모델 모두 시드 하나로 학습한 모델의 시간입니다.

## 다음 질문

- 같은 추론 계산량(차례로 지나는 layer 수 96)을 학습부터 맞추면 어떤가. Middleflow를 latent 14개(7 × 14 = 98)로 학습해야 하며, GPU가 비는 대로 합니다.
