## 한 줄 요약

사용자가 화가와 대화하며 그릴 것을 정하면, 화가가 되묻고 확인한 뒤 **아이템 태그**(장면 하나와 그릴 대상들)를 그림 생성 모델에 넘기는 기능입니다. 규칙으로 움직이는 가상 사용자와 끝까지 대화시켜 잰 목표 달성률은 **김홍도 90.0~93.3%, 정선 96.7~100%**입니다(11월 3일, 규칙 측정). 11월 5일 판에서 "둘 중 아무거나"는 11.7% → 100%, 그림을 다 그린 뒤 "새 그림"을 청하는 경우는 20.0% → 96.7%로 크게 나아졌습니다. 이름 없이 설명하는 요청과 200자 넘는 긴 요청은 아직 약합니다. 사람 평가는 아직 하지 않았습니다.

## 왜 필요했나

- 그림 생성 모델은 짧은 영어 태그 목록을 받아 그림을 그립니다. 사용자는 "강가에 배가 떠 있고 버드나무도 있으면 좋겠어요"처럼 자연스럽게 말합니다. 이 둘을 이어 줄 장치가 필요합니다.
- 단순히 문장을 태그로 바꾸는 것만으로는 부족합니다. 요청이 모호하면 되묻고, 도중에 바꾸거나 빼면 반영하고, 마지막에 확인을 받아야 합니다. 그리고 이 모든 대화를 **화가의 말투**로 해야 합니다.
- 처음에는 전체 캡션(화풍, 구도, 여백까지 담은 긴 설명)을 만들도록 설계했습니다. 그림 생성 모델을 맡은 협력 기관과 맞춰 보니, 우리 쪽은 **장면과 대상을 담은 아이템 태그만** 넘기고 화가 이름, 구도, 선택 태그는 그쪽이 붙이는 구조였습니다. 처음 설계가 맞지 않았다는 것을 인정하고 아이템 태그만 만들도록 다시 짰습니다.

## 용어 풀이

| 용어 | 뜻 | 이 글에서의 실제 값 |
|---|---|---|
| 아이템 태그 | 그림에 들어갈 장면 하나와 대상들의 영어 태그 목록. 첫째가 장면 | `animal painting, pine tree, tiger, rock` |
| 이해 | 사용자 말을 의도, 장르, 대상, 뺄 것 같은 칸으로 바꾸는 단계 | 모델이 JSON 으로 냄 |
| 다음 할 일 규칙 | 지금 상태를 보고 되묻기, 확인, 그리기 중 무엇을 할지 코드로 정하는 단계 | 규칙 코드 |
| 가상 사용자 | 정해진 목표 그림을 가지고 규칙대로 말하는 시험용 상대 | 158대화(기본 60, 돌발 68, 유형 외 30) |
| 아이템 목표 달성 | 대화가 끝까지 가고, 대상 F1 이 0.8 이상이고, 장면이 맞은 비율 | 김홍도 기본 대화 93.3% |
| F1 | 맞힌 대상과 빠뜨린 대상, 잘못 넣은 대상을 함께 반영한 점수. 1이 만점 | 대상 F1 0.98 |
| 아이템 이탈률 | 넘긴 태그 가운데 허용 태그 목록 밖의 비율 | 김홍도 3.4% (21/623) |
| 돌발 행동 | 도중에 요청 바꾸기, 딴 이야기, 처음부터 다시 같은 예외 상황 | 68대화, 17가지 |
| 입력 창 | 긴 대화에서 모델에 넣는 최근 대화 차례 수 | 최근 8차례 |
| 어댑터(LoRA) | 큰 모델은 고정하고 기능별 작은 가중치만 학습하는 방법 | 2에폭, r16, α32 |

## 무엇을 했나

1. **한 턴을 네 단계로 나눔.** 모델에게 모든 것을 맡기지 않고, 모델이 잘하는 이해와 말하기만 맡기고 판단과 태그 조립은 코드로 했습니다(아래 그림).
2. **화가 말씨 지정.** 김홍도는 하오체에 '그대', 정선은 하게체에 '자네'를 씁니다.
3. **학습 대화 생성.** 실제 그림 설명 390개에서 목표 태그와 상황을 배정하고, 대형 언어 모델로 대화를 만든 뒤 규칙 검사와 왕복 검사(대화를 다시 태그로 바꿔 목표와 같은지 확인)를 통과한 것만 썼습니다.
4. **상황 설계.** 요청 변경 5, 도움 요청 4, 진행 방식 변경 6, 지원 범위 밖 요청 5, 주제 이탈 1의 21개 상황으로 시작했고, 이후 대본을 136유형, 14,615대화까지 늘렸습니다. 평가용으로 학습에 없는 유형 9종 30대화를 따로 두었습니다.
5. **평가.** 규칙 기반 가상 사용자와 끝까지 대화시키고, 마지막에 넘긴 태그를 목표와 비교했습니다.
6. **결함을 찾는 즉시 기록.** 결함마다 번호, 영향, 상태를 표로 바로 적었고, 11월 5일까지 약 210건을 기록했습니다.

## 실제 예시

**잘 된 예(김홍도, 실제 엔진 대화)**

| 차례 | 사용자 | 김홍도 |
|---|---|---|
| 1 | 소나무 아래 호랑이를 그려 주세요. | 허허, 소나무 아래 호랑이라니 좋은 소재요. 더 넣고 싶은 것이 있소? |
| 2 | 바위도 하나 있으면 좋겠어요. | 바위도 더하면 소나무와 호랑이가 한결 잘 어울리겠소. 더 보태고 싶은 것이 있소? |
| 3 | 아니요, 됐어요. | 그러면 동물화로 소나무와 호랑이, 바위를 담겠소. 이대로 그려도 좋겠소? |
| 4 | 네, 그대로 그려 주세요. | 알겠소. 소나무와 호랑이, 바위가 어우러진 동물화를 그려 보리다. |

넘긴 아이템 태그: `animal painting, pine tree, tiger, rock`

**잘 된 예(정선)**: 강 위의 배, 배에 앉은 낚시꾼, 강가의 버드나무를 말하자 정선이 "더 넣고 싶은 것이 있는가?"로 되묻고 확인한 뒤 `boating scene, boat, sitting fisherman, willow tree` 를 넘겼습니다.

**안 된 예(김홍도)**: 사용자가 "강가에서 고기 잡는 어부", "버드나무도", "어부 말고 뱃사공으로 바꿔 주세요"라고 했는데, 화가가 빼라고 하지 않은 버드나무까지 빼고 어부의 배를 남겼습니다. 넘긴 태그 `fishing scene, river, fishing boats, boat crew` 중 두 개는 허용 목록 밖이었습니다. 이때 실제 엔진으로 돌린 대화 대본 8건 중 4건에서 이런 누락, 추가, 목록 밖 태그가 나왔습니다(표본이 작음).

**결함 기록 예**: 런타임 규칙이 동음어를 잘못 읽은 경우가 여러 번 나왔습니다.

| 사용자 말 | 잘못 읽은 것 | 결과 |
|---|---|---|
| "간단한 말이라도", "바꾸지 말고" | 말하는 '말'을 동물 '말'로 | `horse` 태그가 더해짐 |
| "집에 걸어 두고 싶어요" | 걸어 둘 곳인 '집'을 그릴 대상으로 | `hanok` 이 더해짐 |

## 결과

### 11월 3일: 아이템 태그만 넘기는 판

표 읽는 법: 가상 사용자와 끝까지 대화시킨 158대화의 규칙 측정값입니다(사람 점수 아님). 위 세 줄은 목표 달성률, 아래는 보조 지표입니다. 김홍도, 정선의 새로 학습한 2.4B 모델에 프롬프트 생성 어댑터를 붙인 값입니다.

| 지표 | 기준 | 김홍도 | 정선 |
|---|---|---|---|
| 목표 달성: 기본 대화(60) | 90% | 93.3% | 100% |
| 목표 달성: 돌발 행동(68) | 80% | 92.6% | 100% |
| 목표 달성: 학습에 없는 유형(30) | 참고 | 90.0% | 96.7% |
| 완성률 | 98% | 100% | 100% |
| 대상 F1, 태그 F1 | 0.90 | 0.98, 0.94 | 1.00, 0.98 |
| 아이템 이탈률 | 10% 이하 | 3.4% (21/623) | 2.1% (14/666) |
| 묻지 않은 색, 거리 질문 | 5% 이하 | 26.6% → 0.0% | 11.4% → 0.6% |

- 마지막 줄은 사용자가 묻지 않았는데 "어떤 색으로 할까?", "가까이 그릴까?"를 되묻던 버릇입니다. 이 질문을 걸러내는 규칙을 넣어 거의 없앴습니다.

### 긴 대화: 최근 8차례만 넣기

표 읽는 법: 사용자가 말한 차례 수마다 50번씩 대화시켜 목표를 맞힌 횟수입니다. 화살표 왼쪽은 대화 전체를 넣었을 때, 오른쪽은 최근 8차례만 넣었을 때입니다(규칙 측정).

| 사용자 차례 | 김홍도 | 정선 |
|---|---|---|
| 6 | 50 → 50 | 41 → 46 |
| 12 | 46 → 46 | 45 → 47 |
| 16 | 43 → 48 | 45 → 43 |
| 20 | **21 → 39** | 38 → 47 |
| 합계(6~20차례) | 260 → 279 / 300 | 259 → 278 / 300 |

- 20차례 대화에서 김홍도는 42%에서 78%로 올랐습니다. 다만 미리 정한 둘째 기준(16, 20차례 모두 90% 이상)은 맞추지 못했습니다.

### 11월 5일 판: 이름 시험 5,184문항

같은 대상을 여러 말로 부르는 시험입니다. 이 판은 학습 자료 결함(아래)을 고친 새 어댑터에, 새 바탕 모델과 고친 규칙, 새 사전을 함께 바꾼 것이라 **어댑터 하나의 효과로 읽으면 안 됩니다.**

표 읽는 법: 유형마다 앞 판 → 새 판의 통과율(%)입니다. 규칙 측정, 사람 점수 아님.

| 유형 | 김홍도 | 정선 |
|---|---|---|
| 둘 중 아무거나("소나무든 대나무든") | 11.7 → **100** | 5.0 → **98.3** |
| 순서로 빼기("두 번째 것은 빼 주세요") | 38.3 → **100** | 30.2 → **100** |
| 둘을 한꺼번에 | 44.9 → 97.4 | 65.8 → 98.7 |
| 제안형("호랑이는 어때요?") | 46.7 → 81.9 | 42.3 → 100 |
| 이름 없이 설명 | 10.7 → **53.6** | 19.0 → **76.2** |
| 처음 보는 말 틀 | 78.3 → 99.8 | 77.2 → 100 |

- 그림 설명 전체를 말로 넣는 시험에서 정확 일치가 12.9%, 8.1%에서 99.6%, 100%로 올랐습니다. 그러나 이 시험의 정답이 학습 정답과 거의 같아서 **처음 보는 요청에 대한 성능을 뜻하지 않습니다.**

### 학습 자료 결함: 긴 대화가 거의 잘려 나감

- 11월 5일 새벽, 학습 자료를 만드는 줄이기 단계가 갈래마다 거의 같은 상한을 줘서, 긴 대화가 학습 자료에서 거의 빠진 것을 찾았습니다. 이해 학습 행 중 긴 대화가 김홍도 1.2%, 정선 1.8%뿐이었습니다.
- 자료 조립을 고쳐 다시 만든 판에서는 긴 대화가 김홍도 23.8%, 정선 31.4%가 됐고, 전체 학습 행은 김홍도 32,933행, 정선 32,978행입니다. 이 판으로 다시 학습한 어댑터가 11월 5일 전달 판에 들어갔습니다.

## 그래서 무슨 뜻인가

- 판단과 태그 조립을 코드로 떼어 낸 구조 덕분에, 모델이 가끔 잘못 알아들어도 허용 목록 밖 태그가 넘어가는 비율은 2~3%대에 머뭅니다.
- 반대로 규칙 코드가 모델이 맞게 읽은 것을 뒤집는 일도 생깁니다('말', '집'). 모델 성능과 규칙 성능을 따로 재야 하고, 결함을 바로 기록해 두는 방식이 원인 추적에 도움이 됐습니다.
- 정해진 시험에서 높게 나와도 시험 정답이 학습과 비슷하면 일반화를 말할 수 없습니다. 이런 값은 따로 표시합니다.

## 한계와 남은 일

- **사람 평가가 없습니다.** 모든 값은 규칙 기반 가상 사용자와의 대화로 잰 것입니다.
- **실제 그림 생성까지 이어 본 평가가 없습니다.** 넘긴 태그로 그린 그림이 요청과 맞는지는 아직 보지 않았습니다.
- **긴 요청에 약합니다.** 200자가 넘는 요청의 합격률이 김홍도 50.0%입니다.
- **"무엇을 그릴 수 있나요?" 같은 질문에 약합니다.** 이 유형의 통과율은 0~13%였습니다.
- 이름 없이 설명하는 요청은 53.6%, 76.2%에 머물러 있습니다.
- 실제 사용자 대화 548개를 읽으며 찾은 결함들은 다음 판에서 고칩니다.
