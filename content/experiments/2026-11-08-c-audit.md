## 질문

그동안의 스모크·파일럿 실험 방법에 결과를 흔드는 문제가 없었는가. 일지 요약이 아니라 코드, 실행 로그, 원자료로 확인했습니다.

## 결과

| 문제 | 확인한 내용 | 영향 |
|---|---|---|
| 생성 설정 덮어쓰기 | 모델의 기본 생성 설정(top_p 0.8, 반복 벌점 1.05)이 계획한 값(top_p 1, 반복 벌점 1)을 덮어쓴 실행이 있었음. 일부는 기록이 정정되지 않았음 | 해당 실행의 설정 기록 정정 |
| 짧은 출력 상한 | 생성 약 2,300개가 1,024~8,192 상한에서 돌았고 12%가 상한에 걸림. 25% 이상 잘린 실험이 다수 | 그 기준으로 폐기된 판정 대부분이 재검토되지 않음 |
| 검정력 부족 | 같은 문항 안 log 길이 표준편차 약 0.44. 진짜 20% 감소를 잡을 확률은 문항 1~2개 × 4회면 11~17%, 4문항 × 8회 약 50%, 8문항 × 16회 98% | 대부분의 실패는 효과 부재의 근거가 아님 |
| 바닥 효과 기준 | 합성 과제의 주 기준이 모든 조건에서 사실상 0 | 일부 방향이 이 기준으로 폐기됨 |
| 사례 추적형 가설 | 직전 출력 하나의 특이 사례로 가설을 만들고 새 1~2문항에서 재현 시도 | 탐색 자료와 확인 자료가 분리되지 않음 |
| 모델 밖 상태 입력 | 손으로 쓴 앞부분이나 다른 모델 출력을 넣은 실험이 많음 | 모델이 실제로 가지 않는 상태일 수 있음 |
| 학습 seed | 모든 체크포인트가 학습 seed 1개 | A2와 QFFT 사이의 작은 차이는 학습 잡음과 분리 안 됨 |
| 측정 지표 | 공식 긴 추론 지표는 wait 단어 규칙 | 표지에 개입한 실험의 길이 판정에 단독으로 못 씀 |

## 권고

- 폐기된 핵심 방향은 자연 문항, 32k 상한, 최소 8문항 × 16회로 다시 판정합니다.
- 탐색 문항과 확인 문항을 처음부터 나눕니다.
- 개입할 상태는 그 모델 자신의 자연 생성에서 가져옵니다.
- 생성 때 실제 적용된 설정을 코드로 확인하고 기록합니다.
