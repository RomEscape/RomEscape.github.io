## 한 줄 요약

LLM 자동 평가가 낮은 점수에 붙인 이유 가운데 1위는 **"지어냄"(33.0%)**이었습니다. 질문을 나눠 보니 **인물 프로필에 근거가 충분한 질문은 멀티턴 5.06~5.20점, 근거가 없는 질문은 3.26~3.57점**이었고, 근거가 같으면 화가가 조수미보다 낮지 않았습니다. 차이는 프로필 분량이었습니다(조수미 25,151자, 김홍도 3,335자, 정선 2,618자). 공개 사료에서 **인물마다 사실 약 300개**를 모아 프로필을 1만 6천~1만 8천 자로 다시 쓰고, 출처와 대조해 틀린 사실을 고친 뒤 **학습 자료의 검색 문단과 답까지 함께 고쳐 썼습니다.** 새 자료로 학습한 2.4B 모델은 그때 서비스 모델보다 점수가 높았고(김홍도 한 턴 5.14 → 5.76, 정선 5.38 → 5.93), 답도 길어졌습니다(중앙값 130 → 195자, 132 → 184자). 점수는 모두 LLM 자동 평가이며 사람 점수가 아닙니다.

## 왜 필요했나

- 새 평가 방식(gpt-6-luna, 프로필 전체 제공)으로 재니, 김홍도와 정선의 사실 영역 점수가 낮았습니다.
- 처음에는 "화가의 말투나 모델 크기 문제"를 의심했지만, 평가 모델이 남긴 판정문을 모아 보니 감점 이유가 대부분 사실 쪽이었습니다.
- 모델은 학습 자료를 따라 합니다. 학습 자료에 프로필에 없는 일화가 들어 있으면 모델도 지어냅니다. 그래서 프로필과 학습 자료를 함께 고쳐야 했습니다.

## 용어 풀이

| 용어 | 뜻 | 이 글에서의 실제 값 |
|---|---|---|
| 프로필 | 인물의 생애, 작품, 성격, 말투를 적은 글. 학습 자료를 만들 때와, 실행 중 질문과 관련된 문단을 찾아 붙일 때 씀 | 옛 김홍도 프로필 3,335자 |
| 검색 증강 생성(RAG) | 질문과 비슷한 프로필 문단을 찾아 답 근거로 붙여 주는 방식 | 질문마다 상위 5개 문단 |
| 지어냄 | 프로필이나 사료에 없는 사실을 사실처럼 말하는 것 | 판정문 감점 이유 33.0% |
| 근거 충분, 일부, 없음 | 질문에 답할 사실이 프로필에 얼마나 있는지를 질문마다 붙인 분류 | 멀티턴 충분 5.06~5.20점 |
| 출처 대조 | 새 프로필의 문장을 하나씩 원문 자료와 맞춰 보는 것 | 김홍도 원문 확인 74건 중 틀림 5건 |
| 특수 토큰 | 모델이 한 덩어리로 읽는 약속된 기호. 대화에서 누가 말하는지 표시함 | EXAONE의 `[|assistant|]`는 특수 토큰이 아님 |
| 손실 | 모델의 예측이 정답과 얼마나 다른지 나타내는 값. 학습은 이 값을 줄이는 쪽으로 모델을 고침 | 답 글자에만 계산 |
| 에폭(ep) | 학습 자료 전체를 한 바퀴 도는 단위 | ep4 = 4바퀴 학습 |
| LLM 자동 평가 | 대형 언어 모델이 기준표로 채점한 점수. 사람 점수가 아님 | gpt-6-luna + 서비스 패키지 프로필, 7영역 1~7점 |

## 무엇을 했나

1. **약한 곳 찾기.** 그때 서비스 모델의 한 턴 100문항, 멀티턴 50주제 점수를 질문별로 모으고, 질문마다 프로필 근거(충분, 일부, 없음)와 질문 유형을 붙였습니다. 판정문 3,300개에서 감점 이유를 분류했습니다.
2. **공개 사료로 사실 모으기.** 실록 같은 사료와 연구 자료에서 사실을 모았습니다. 정선 299개(자료 73곳), 김홍도 300개(자료 107곳)입니다. 출처가 있고 다른 자료와 부딪히지 않는 사실과, 학설이 갈리는 사실을 나눠 적었습니다.
3. **새 프로필 쓰기.** 모은 사실로 인물마다 90개 절의 프로필을 새로 썼습니다. 인물이 살아서 알 수 없는 일(자기 사후의 평가, 몰년 등)은 말하지 않도록 했습니다.
4. **출처 대조.** 새 프로필을 원문과 다시 맞췄습니다. 정선은 원문 확인 92줄 중 4줄, 김홍도는 74건 중 5건이 틀려 고쳤습니다. 최종 프로필은 정선 16,334자, 김홍도 17,974자입니다(옛 판 2,618자, 3,335자).
5. **학습 자료 고쳐 쓰기.** 프로필을 바꾸면 학습 자료도 바꿔야 합니다. 학습 자료의 사용자 차례에는 검색된 프로필 문단이 붙어 있기 때문입니다.
   - 모든 행의 검색 문단을 새 프로필에서 실행 때와 같은 방식으로 다시 뽑음(안전 자료 포함)
   - 답을 전부 점검해 지어낸 사실, 프로필과 부딪히는 말, 지나친 단정, 사후 정보를 고쳐 씀
   - 측정에서 약했던 질문 유형을 보강하는 대화를 더함(김홍도 236개, 정선 225개)
   - 답이 너무 짧지 않게 늘임(대화 답 중앙값 297자)
6. **채팅 형식 전수 점검.** 학습 자료가 EXAONE 공식 대화 형식과 글자까지 같은지 확인하다가 결함 하나를 찾았습니다. 답 시작 표시 `[|assistant|]`가 특수 토큰이 아니라 `[`, `|`, `ass`, `istant`, `|`, `]` 여섯 조각으로 쪼개졌습니다. 답이 `(`나 `{`로 시작하면 앞의 `]`와 합쳐져 한 토큰이 되고, 그래서 **답의 첫 글자에는 손실이 걸리지 않았습니다.** 실행할 때는 프롬프트가 `]`로 끝나므로, 모델은 그 자리에서 무엇을 낼지 배운 적이 없게 됩니다. 그림 요청 대화 자료는 답 앞에 공백 하나를 넣어 다시 학습했고, 같은 문제가 있는 조수미 자료는 다음 재학습 때 고칩니다. 화가 대화 자료는 원래 답 앞에 공백이 있어 해당하지 않았습니다.
7. **새 자료로 학습.** 김홍도 5,443행, 정선 5,106행으로 2.4B 모델을 먼저 10에폭 학습하고 모든 에폭을 재서 골랐습니다. 이어 같은 자료로 7.8B 모델도 다시 학습했습니다.

## 실제 예시

학습 자료에서 찾은 틀린 답의 실제 예입니다(김홍도 자료).

- 사용자: "1726년에 태어나셨고 … 맞는 건가요?"
- 자료 속 답: "그 기록은 맞소."
- 사실: 김홍도는 1745년생입니다. 틀린 전제를 바로잡아야 할 자리에서 맞장구를 쳤습니다. 이런 답을 전수 점검에서 고쳤습니다.

옛 프로필과 사료가 어긋난 예입니다.

- 옛 프로필은 김홍도가 연풍 현감 시절 "백성을 보살폈다"고 적었지만, 실록에는 그를 처벌하자는 청원이 있습니다. 새 프로필은 원문 기록에 맞췄습니다.
- 옛 프로필의 일부 일화(풍속도첩을 "가장 아꼈다" 같은 표현)는 근거를 찾지 못해 단정하지 않는 쪽으로 바꿨습니다.

표 읽는 법: 감점된 답(5점 이하)에 평가 모델이 붙인 이유의 비율입니다. 한 답에 이유가 여러 개 붙을 수 있습니다. LLM 자동 평가입니다.

| 감점 이유 | 비율 |
|---|---|
| 지어냄 | 33.0% |
| 일반론으로 얼버무림 | 20.0% |
| 근거 부족 | 15.2% |
| 모르는 것을 모른다고 하지 않음 | 10.0% |
| 사실 틀림 | 7.1% |
| 앞 답 반복(거의 멀티턴) | 6.6% |

표 읽는 법: 질문을 프로필 근거 정도로 나눠 7영역 평균을 냈습니다. 순서는 조수미, 김홍도, 정선입니다. 아래 두 줄은 근거가 "충분"한 질문의 비율입니다. LLM 자동 평가입니다.

## 그래서 무슨 뜻인가

- **"지어냄"의 뿌리는 짧은 프로필과 그 위에서 만든 학습 자료였습니다.** 근거가 같으면 화가 모델도 조수미 모델만큼 답했습니다. 화가가 낮았던 것은 근거 있는 질문이 적었기 때문입니다.
- **프로필을 고치면 학습 자료를 함께 고쳐야 합니다.** 검색 문단이 학습 자료에 그대로 들어가 있고, 그 위의 답도 옛 프로필을 따라 쓰였기 때문입니다.
- **형식 결함은 점수로는 안 보입니다.** 첫 글자 손실이 빠지는 문제는 대화 형식을 토큰 단위로 직접 확인해야 찾을 수 있었습니다.

## 한계와 남은 일

- 사실 수집은 대부분 웹 자료의 요약으로 읽었고, 사료 원문은 일부만 확인했습니다. "확인된 사실"은 "출처가 있고 부딪히는 자료를 찾지 못함"이라는 뜻입니다.
- 김홍도의 몰년처럼 자료끼리 크게 엇갈리는 사실은 모델이 단정하지 않게만 했습니다.
- 점수는 모두 LLM 자동 평가입니다. 새 모델의 사람 평가는 아직 없습니다.
- 조수미 자료도 다시 만들려 했지만(행사에서 받은 의견을 반영한 판), 여러 지표가 서로 당겨 미리 정한 합격 기준을 세 번 넘지 못해 보류했습니다. 조수미 서비스 모델은 기존 판을 그대로 씁니다.
- 새 프로필 일부 문장이 모델용 주의 문구("단정하지 않는다" 등)여서 대사로 새는 문제가 뒤에 발견되었습니다([기억을 묻는 질문과 프로필 주석 문제](2026-11-06-persona-memory-data.html)).
