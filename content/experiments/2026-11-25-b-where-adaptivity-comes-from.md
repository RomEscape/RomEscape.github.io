## 한 줄 요약

- 연구의 중심 질문을 다시 잡았습니다. **A2, QFFT, 시스템 프롬프트 제거, 문제 글만 넣기는 모두 "긴 풀이만 배운 모델이 쉬운 문제는 짧게 풀게" 만듭니다. 이 공통의 영향은 모델 안 어디서 오는가.**
- 저장된 답 500문항으로 먼저 확인한 것은 세 가지입니다.
  1. 답의 첫머리는 조건마다 거의 전부 아니면 전무입니다. 학습한 긴 풀이의 시작인 "Okay"이거나, 학습 전 모델의 시작인 "To"입니다.
  2. 어느 문제를 길게 풀지는 모든 파인튜닝 모델이 거의 같게 정합니다(문항 순위 상관 0.86–0.95). 늘 길게 푸는 표준 SFT도 같습니다. 이 순서는 학습 전 모델이 그 문제에서 보이는 불확실성과도 0.61–0.63으로 맞습니다.
  3. "Okay"로 시작하면 같은 문제에 약 1,200 tokens가 고정으로 붙고 나머지는 1.2배쯤 됩니다. 쉬운 문제에서도 거의 항상 되묻습니다(90%). "To"로 시작하면 어려운 문제일수록 되묻습니다(15% → 58%).
- 그래서 지금의 답은 이렇습니다. **난도에 맞춰 길이를 정하는 판단은 모델이 원래 갖고 있고 모든 모델에 있습니다. 방법들이 없애는 것은 그 판단이 아니라, "Okay" 첫머리에 묶여 있는 고정 비용과 항상 되묻는 습관입니다.**
- 모델 안에서 본 첫 결과는 이렇습니다. **같은 행동이 서로 다른 내부 상태에서 나옵니다.** QFFT는 표준 입력을 받으면 내부 상태가 학습 전 모델에 가깝고(학습 전의 계산이 그대로 남아 있음), A2는 A1만큼 학습 전 모델에서 멀면서 긴 풀이로 시작한다는 성분만 다릅니다. 긴 풀이로 시작하는 상태가 켜지는 지점은 가중치의 한 곳이 아니라 여러 층에 나뉘어 있었습니다. 자세한 것은 아래 "모델 안에서 본 것"에 있습니다.
- 첫 토큰(Okay, To)을 직접 조작하는 것은 이미 알려진 방법이라 방법으로 삼지 않고, 모델이 어느 상태인지 알려 주는 표시로만 씁니다.

## 연구 질문

| 순서 | 내용 |
|---|---|
| 본 현상 | 긴 풀이(Long CoT)만으로 학습한 표준 SFT는 쉬운 문제에도 길게 풉니다. 그런데 서로 다른 조치 다섯 가지가 같은 결과를 냅니다. 학습에서 질문을 빼고 첫 토큰의 loss를 뺀 A2, 질문과 시스템 프롬프트 없이 학습한 QFFT, 추론 입력에서 시스템 프롬프트를 빼기, 프롬프트 템플릿까지 빼고 문제 글만 넣기, 답의 첫 토큰을 To로 두기. 모두 쉬운 문제는 짧게, 어려운 문제는 길게 풀게 만듭니다. |
| 든 의문 | 이 조치들은 학습을 바꾸기도 하고 입력을 바꾸기도 하는데 왜 같은 결과가 나오는가. 두 가지를 생각할 수 있습니다. (가) 학습 전 모델의 짧게 푸는 습관이 모델 안에 깊이 남아 있다가 다시 올라오는 것인가. (나) 긴 풀이로만 내보내던 제약이 풀려 모델이 스스로 고를 수 있게 되는 것인가. 어느 쪽이든 그것이 켜지고 꺼지는 지점은 모델 안 어디에 있는가(attention head, 특정 방향의 vector, 층, 가중치, 입력 토큰의 embedding). 그리고 "쉬운 문제는 짧게, 어려운 문제는 길게"라는 판단 자체는 어디서 오는가. |
| 그때까지 안 해 본 것 | 조치마다 길이와 정답률을 따로 쟀습니다. 여러 조치를 한 현상으로 묶어 "무엇이 공통인가"를 물은 적이 없었습니다. 내부 분석은 한 모델 안에서 입력만 바꾸거나(11월), 두 모델의 다음 토큰 분포를 견주는 데(9월) 그쳤고, 원인 지점을 넓게 훑은 적이 없었습니다. |
| 그래서 한 것 | (1) 저장된 답으로 조건마다 첫머리와 길이를 문항 단위로 견줬습니다. (2) 같은 모델, 같은 입력, 같은 문제에서 첫머리만 다르게 나온 답을 견줬습니다. (3) 문항별 길이를 학습 전 모델의 불확실성과 견줬습니다. (4) 원인이 있을 수 있는 곳을 표로 만들고 값싼 확인부터 돌리고 있습니다. |
| 답(지금까지) | 난도에 맞춰 길이를 정하는 판단은 모든 모델에 있고 학습 전 모델의 불확실성과 맞습니다. 조치들이 공통으로 없애는 것은 그 위에 얹힌 고정 비용과 항상 되묻는 습관입니다. 모델 안에서는 (가)와 (나)가 방법마다 다르게 맞았습니다. QFFT는 학습 전 모델에 가까운 상태이고, A2는 파인튜닝된 채 긴 풀이로 시작하는 성분만 다른 상태입니다. |
| 다음 의문 | 그 판단은 모델 안 어디에 있는가. "Okay" 첫머리는 모델 안 어디서 켜지는가. 판단은 남기고 고정 비용만 없애는 가장 직접적인 방법은 무엇인가. |

## 용어 풀이

| 용어 | 뜻 | 이 글에서의 예 |
|---|---|---|
| Long CoT | 긴 풀이. 혼잣말하듯 따져 보고 되묻는 풀이 방식 | "Okay, so I need to find … Hmm, let me think. … Wait, …" |
| 표준 SFT | 시스템 프롬프트 + 질문 + 긴 풀이로 학습한 비교 기준 모델 | MATH500에서 한 문제에 평균 6,576 tokens |
| A1, A2 | A1은 학습에서 질문을 뺀 모델, A2는 거기에 응답 첫 토큰의 loss까지 뺀 모델 | 둘의 학습 입력은 같습니다 |
| QFFT | 질문과 시스템 프롬프트 없이 풀이만으로 학습한 모델 | Question-Free Fine-Tuning |
| 표준 입력 | 표준 평가의 입력. 프롬프트 템플릿 + 시스템 프롬프트 + 문제 | 시스템 프롬프트는 "Please reason step by step, and put your final answer within \boxed{}." |
| 제거 입력 | 표준 입력에서 시스템 프롬프트만 뺀 입력 | 프롬프트 템플릿과 문제는 남습니다 |
| 첫머리 | 답의 첫 낱말 | Okay나 Alright로 시작하면 "Okay류", 그 밖은 대부분 "To" |
| Level | MATH500이 문항마다 붙인 난도(1이 가장 쉽고 5가 가장 어려움) | Level 1은 43문항, Level 5는 134문항 |
| 불일치 | 학습 전 모델이 같은 문제를 16번 풀었을 때, 가장 많이 나온 답이 아닌 답의 비율 | 16번 모두 같은 답이면 0 |
| 순위 상관 | 두 값의 순서가 얼마나 같은가(1이면 순서가 같고 0이면 무관) | 문항별 길이의 순서를 두 조건에서 견줍니다 |
| logit | 모델이 다음 토큰 후보마다 매기는 점수. 높을수록 그 토큰이 나올 확률이 높습니다 | Okay의 logit에서 To의 logit을 뺀 값이 양수이면 Okay 쪽 |
| 시작 상태 | 입력의 마지막 토큰 위치(답이 시작되는 자리)에서 각 층이 내는 내부 값 | 3,584개의 수로 된 벡터 |
| embedding | 토큰 하나를 모델이 읽는 수의 줄로 바꾼 것. 토큰마다 한 행 | `<\|im_start\|>` 토큰의 행 |
| attention head | 한 층 안에서 앞 토큰들의 정보를 가져오는 부품. 이 모델은 층마다 28개 | 시스템 프롬프트 토큰을 읽어 오는 head |
| nats | 두 확률 분포가 얼마나 다른지 재는 단위(0이면 같음) | A2와 학습 전 모델의 첫 토큰 분포는 0.17 nats |

**표 읽는 법.** 한 줄이 "모델 + 추론 입력" 하나입니다. ACC는 정답률(%), Tokens는 답 하나의 평균 출력 tokens입니다. "구분"이 줄의 뜻입니다. 기준은 학습 방법이 다른 모델들을 표준 평가 그대로 잰 값이고, 굵게 적은 A2와 QFFT가 견줄 상대입니다. 방법은 표준 SFT를 다시 학습하지 않고 추론 입력만 바꾼 값입니다. 문제 글만 넣는 줄이 방법 QOI이고, 시스템 프롬프트만 뺀 줄은 그 부분 적용(프롬프트 템플릿은 남김)입니다. 참고는 같은 입력 변경을 다른 모델에 얹어 본 값입니다. "대기"는 지금 돌고 있는 칸입니다.

- **모델.** Base는 파인튜닝 전의 Qwen2.5-7B-Instruct입니다. 나머지는 모두 LIMO 817문항으로 학습했습니다. SFT는 QFFT 논문이 비교 기준으로 쓴 표준 SFT로, 시스템 프롬프트와 질문, 긴 풀이를 그대로 학습한 모델입니다. A1은 질문을 지우고, A2는 질문을 지우고 응답 첫 토큰의 loss까지 빼고, QFFT는 논문 방법대로 질문 없이 풀이만으로 학습한 모델입니다.
- **무엇을 견주는가.** A2와 QFFT는 학습 방법을 바꿔 새로 학습한 모델입니다. 방법 줄은 표준 SFT의 가중치를 그대로 두고 추론 입력만 바꾼 것입니다. A2나 QFFT 위에 얹은 것이 아니라, A2, QFFT와 나란히 견주는 다른 길입니다. 같은 입력 변경을 A1, A2, QFFT에 얹어 본 값은 참고 줄에 따로 두었습니다.
- **추론 입력.** 기본 프롬프트는 프롬프트 템플릿, 시스템 프롬프트 "Please reason step by step, and put your final answer within \boxed{}.", 질문으로 이루어집니다. 시스템 프롬프트 제거는 거기서 시스템 프롬프트만 뺀 입력이고, 문제 글만은 프롬프트 템플릿까지 빼고 질문 글자만 준 입력입니다. 실제 문자열은 아래 "실제 입력과 실제 답"에 있습니다.
- **크기.** GSM8K 1,319문항, MATH500 500문항, AIME25 30문항입니다. 기본 프롬프트 줄은 문항마다 16회, 나머지 줄은 4회 풀게 했습니다. 최대 32,000 tokens입니다.
- **채점.** GSM8K와 MATH500의 ACC는 `\boxed{}` 없이 끝난 답을 직접 읽어 반영하고, 표기만 다른 같은 답을 맞게 고친 값입니다(GSM8K는 평가 자료의 정답 16문항도 바로잡았습니다). AIME25는 공식 채점 스크립트 값 그대로입니다.
- **읽기.** MATH500에서 표준 SFT에 문제 글만 준 줄(QOI)은 ACC 81.4%, 4,221 tokens입니다. A2(81.3%, 4,587)와 QFFT(81.4%, 4,630)와 정답률이 같고 8–9% 짧습니다. GSM8K와 AIME25의 같은 칸은 아직 돌지 않았습니다. 참고 줄을 보면 A2와 QFFT도 시스템 프롬프트를 빼면 더 짧아집니다(3,948, 4,122 tokens).

## 실제 입력과 실제 답: 같은 모델, 같은 입력, 같은 문제에서 첫머리만 다른 두 답

## 결과 1: 첫머리는 조건마다 거의 전부 아니면 전무입니다

**표 읽는 법.** 한 줄이 "모델 + 입력" 하나입니다. "Okay류로 시작"은 그 조건의 답 가운데 Okay나 Alright로 시작한 답의 비율입니다. Level 1과 Level 5의 값은 그 난도 문항의 평균 출력 tokens입니다. MATH500 500문항이고 표준 입력은 문항마다 16번, 나머지는 4번 푼 저장분입니다.

## 결과 2: 첫머리는 모델이 난도를 보고 고르는 것이 아닙니다

"짧게 풀 문제는 To, 길게 풀 문제는 Okay"로 모델이 고르는 것인지 확인했습니다. 둘이 섞여 나오는 조건(표준 SFT, 제거 입력)에서 문항별로 봤습니다.

| 확인한 것 | 값 |
|---|---|
| 네 번 모두 같은 첫머리로 시작한 문항 | 500문항 가운데 272문항(답마다 무작위라면 63문항쯤) |
| 문항의 Okay류 비율과 Level의 순위 상관 | −0.13 |
| A1, 표준 입력에서 같은 상관 | −0.32 |

문항마다 첫머리가 거의 정해지지만 난도를 따르지 않습니다. 어려운 문항일수록 Okay류가 오히려 조금 적습니다.

같은 문항에서 Okay류 답과 To 답이 둘 다 나온 228문항만 골라, 같은 문항끼리 견줬습니다.

**표 읽는 법.** 한 줄이 Level 하나입니다. 왼쪽 두 칸은 그 Level 문항의 평균 tokens, 오른쪽 두 칸은 답 가운데 "wait"가 한 번이라도 나온 답의 비율입니다. 같은 모델, 같은 입력, 같은 문항이고 첫머리만 다릅니다.

| Level | 문항 수 | Okay류 답 tokens | To 답 tokens | wait가 나온 답: Okay류 | To |
|---|---:|---:|---:|---:|---:|
| 1 | 13 | 2,219 | 780 | 89.7% | 15.4% |
| 2 | 41 | 2,416 | 1,377 | 93.9% | 23.2% |
| 3 | 45 | 3,260 | 2,580 | 95.2% | 37.0% |
| 4 | 64 | 7,233 | 4,561 | 97.9% | 43.5% |
| 5 | 65 | 10,650 | 6,986 | 98.5% | 57.9% |

- 같은 문제에서 Okay류로 시작하면 길이가 문항별로 2.0배(기하평균)이고 공식 채점 정답률은 77.3% 대 75.4%로 비슷합니다. 길게 풀어야 해서 Okay가 나오는 것이 아니라, Okay로 시작하면 같은 문제도 길게 풉니다.

- 늘어난 분량은 답을 낸 뒤의 재확인이 아닙니다. 첫 `\boxed{}` 뒤의 분량은 두 쪽 모두 중앙값이 7–8 tokens입니다. 답에 이르기 전의 1인칭 탐색(평균 36.7번 대 8.9번)과 되묻기(wait 평균 38.0번 대 13.6번)에 쓰입니다.

## 결과 3: 어느 문제를 길게 풀지는 모든 모델이 같게 정하고, 학습 전 모델의 불확실성과 맞습니다

**표 읽는 법.** 값은 문항별 평균 길이(log tokens)의 순서가 두 조건에서 얼마나 같은지를 Level 안에서 잰 순위 상관입니다. Level 안에서 쟀으므로 "어려운 Level이 길다"는 것은 이미 빼고 본 값입니다. 대괄호는 문항 재표집으로 낸 95% 구간입니다.

| A2 표준과 표준 SFT(문제 글만) | 0.87 [0.83, 0.90] |

## 결과 4: 방법들이 없애는 것은 고정 비용입니다

Okay류로 시작하는 조건의 문항별 길이(y)를 To로 시작하는 조건의 같은 문항 길이(x)로 맞췄습니다(문항별 중앙 tokens, 이상값에 덜 민감한 Theil–Sen 맞춤).

| Okay류 조건 (y) | To 조건 (x) | 맞춘 식 | 문항별 차의 중앙값 |
|---|---|---|---:|
| 표준 SFT, 표준 입력 | A2, 표준 입력 | 1,226 + 1.26 x | 1,146 tokens |
| 표준 SFT, 표준 입력 | QFFT, 표준 입력 | 1,223 + 1.16 x | 1,084 tokens |
| A1, 표준 입력 | A2, 표준 입력 | 1,041 + 1.18 x | 929 tokens |
| 표준 SFT 제거 입력의 Okay류 답 | 같은 문항의 To 답 | 1,242 + 1.20 x | 940 tokens |
| 대조: A2, 표준 입력 | QFFT, 표준 입력 | 9 + 0.91 x | 20 tokens |

- Okay류로 시작하면 문항마다 약 1,000–1,200 tokens가 고정으로 붙고 나머지는 1.2배쯤 됩니다. 두 To 조건끼리 견주면 고정 비용이 없습니다(9 tokens).
- 쉬운 문제는 본래 길이가 500 tokens 안팎이라 이 고정 비용 때문에 2.5–2.9배가 됩니다. 어려운 문제는 본래 길이가 길어 1.2배에 그칩니다. 겉으로 보이는 "쉬운 문제는 짧게, 어려운 문제는 길게"와 "늘 길게"의 차이는 판단의 차이가 아니라 이 고정 비용이 있는가 없는가입니다.
- 이것은 사전 규칙 없이 본 탐색 결과입니다. 11월 24일의 [남는 비율 분석](2026-11-24-b-leak-fraction-qfft.html)이 본 것(쉬운 문제에서는 조금, 어려운 문제에서는 거의 전부 남는다)과 같은 현상을 다른 척도로 본 것이고, 새로 더한 것은 표준 SFT까지 포함한 순서의 일치와 학습 전 모델의 불확실성과의 관계입니다.

## 모델 안에서 본 것 (진행 중)

조치들이 짧게도 풀게 만드는 까닭으로 두 가지를 생각할 수 있습니다.

| 표준 SFT(표준 입력, Okay로 시작)와 학습 전 모델 | 0.74 | 0.67 | 0.80 | 가장 멉니다 |
| A2와 QFFT | 0.46 | 0.47 | 0.46 | 행동은 같은데 서로 멉니다 |

- **두 가설이 방법마다 다르게 맞았습니다.** QFFT는 가설 가입니다. 표준 입력을 받으면 내부 상태가 학습 전 모델에 가깝습니다. 프롬프트 템플릿 없이 학습해서, 이 입력을 처리하는 계산이 거의 바뀌지 않은 채 남아 있습니다.
- A2는 가설 나입니다. 내부 상태는 A1만큼 학습 전 모델에서 멀고 A1과는 가깝습니다. 파인튜닝된 상태 그대로인데 긴 풀이로 시작한다는 성분만 다릅니다.
- A2와 QFFT는 출력이 거의 같은데(문항별 길이의 순위 상관 0.95) 모델 안에서는 서로 다른 길로 왔습니다.
- 미리 정한 기준(To 조건의 거리 ÷ Okay 조건의 거리가 0.5 이하이면 가설 가 쪽, 0.8 이상이면 가설 나 쪽)으로 A2 ÷ A1은 1.01, QFFT ÷ 표준 SFT는 0.37이었습니다. 미리 적은 예측은 "둘 다 가설 나 쪽"이었고 QFFT에서 틀렸습니다.

### 2. 긴 풀이로 시작하는 상태가 켜지는 지점, 지금까지 좁혀진 만큼

| 위치 | 확인 방법 | 결과 |
|---|---|---|
| 프롬프트 템플릿 토큰의 입력 embedding | 두 토큰의 행만 학습 전 값으로 되돌림 | 일부가 여기 있습니다(아래 4) |
| 시작 위치의 14층까지 | 표준 SFT의 시작 상태를 다른 조건에 넣음 | 여기까지 "긴 풀이로 시작하라"는 신호가 만들어집니다(아래 3) |
| 시작 위치의 14–22층 | 반대로 넣어 봄 | 입력을 여러 번 다시 읽어 다시 켭니다(아래 3) |
| 21–24층 | 층별로 출력 쪽을 읽음 | 여기서 출력으로 바뀝니다(아래 5) |
| 정규화 층 | 가중치 견주기 | 아닙니다(여섯 모델 모두 변화 0.00%) |
| 한 층 구간의 가중치 | 층 구간을 다른 모델 것으로 바꿔 끼움 | 한 구간에 모여 있지 않습니다. 일곱 구간에 고르게 나뉘어 있습니다 |

원인은 가중치의 한 곳이 아니라 여러 층에 나뉘어 있고, 입력을 여러 번 다시 읽는 과정에 걸쳐 있습니다. 첫 토큰의 loss 하나만 다르게 학습한 A1과 A2의 차이도 한 층 구간에 있지 않았습니다(구간별 몫 0.04–0.24, 더하면 1쯤).

### 3. 표준 SFT의 시작 상태를 다른 모델에 넣으면

같은 문제에서 표준 SFT의 시작 상태를 꺼내 다른 모델의 같은 자리에 넣었습니다. 넣는 것은 표준 SFT의 (표준 입력 상태 − 시스템 프롬프트 제거 상태)입니다. 앞 토큰들의 계산은 받는 모델 것 그대로 둡니다.

**표 읽는 법.** 값은 넣은 뒤 답이 긴 풀이의 첫머리로 시작할 확률입니다(25문항 평균). 넣기 전 값이 "자기 값"입니다.

| 받는 모델 | 입력 | 자기 값 | 14층에 넣음 | 18층에 넣음 | 22층에 넣음 | 미리 적은 예측 |
|---|---|---:|---:|---:|---:|---|
| 표준 SFT(방법 확인) | 시스템 프롬프트 제거 | 0.52 | 1.00 | 1.00 | 1.00 | 켜진다(맞음) |
| A1 | 시스템 프롬프트 제거 | 0.01 | 0.79 | 0.96 | 0.99 | 켜진다(맞음) |
| A2 | 표준 | 0.00 | 0.21 | 0.81 | 0.95 | 안 켜진다(틀림) |
| QFFT | 표준 | 0.00 | 0.02 | 0.48 | 0.93 | 켜진다(틀림) |

- 반대로 QFFT의 시작 상태를 표준 SFT에 통째로 넣으면, 18층까지 넣어도 0.98로 남고 22층에 넣어야 0.10이 됩니다. 표준 SFT는 한 층에서만 정하지 않고 14–22층에 걸쳐 입력을 여러 번 다시 읽습니다.
- 받은 상태를 긴 첫머리로 잇는 정도는 A1 > A2 > QFFT 순입니다. 시스템 프롬프트로 학습한 A1과 A2에는 그 처리가 남아 있고, 본 적 없는 QFFT에는 덜 남아 있습니다.
- 다른 문제의 표준 SFT 상태를 넣어도 값이 같았습니다(A2, 18층에서 0.80 대 0.79). 옮겨지는 것은 문제의 내용이 아니라 상태의 종류입니다.

### 4. 프롬프트 템플릿 토큰의 embedding

| 견준 것 | 값 |
|---|---|
| 전체 가중치의 변화량(여섯 모델) | 0.90–0.91%로 모두 같음 |
| 입력 embedding에서 값이 바뀐 행 | 약 15만 행 가운데 1만 3천 행(학습 자료에 나온 토큰) |
| 그 행들의 상대 변화량, 99번째 백분위 | 1.5% |
| `<\|im_start\|>` 행의 상대 변화량 | 표준 SFT 70%, A1 48%, A2 52%, QFFT 0% |
| `<\|im_end\|>` 행의 상대 변화량 | 표준 SFT 41%, A1 37%, A2 34%, QFFT 0% |

- 프롬프트 템플릿의 두 토큰만 유독 크게 바뀌었습니다. 프롬프트 템플릿 없이 학습한 QFFT는 이 두 행이 전혀 바뀌지 않았습니다. 학습 전 모델에서 이 두 행은 크기가 다른 행의 1%쯤으로 아주 작아서, 절대 변화는 작지만 방향은 크게 달라졌습니다.
- **이 두 행만 학습 전 값으로 되돌려 봤습니다.** 토큰은 입력에 그대로 두고 값만 바꾼 것입니다. 표준 SFT에 시스템 프롬프트를 뺀 입력을 주면 긴 첫머리로 시작할 확률이 0.52에서 0.19로 줄었습니다. 시스템 프롬프트가 있으면 1.00 그대로입니다. 미리 정한 기준(0.10 이하이면 "두 행의 값이 켠다", 0.40 이상이면 "아니다")으로는 "일부"입니다.
- 바꾼 것은 가중치 76억 개 가운데 7,168개입니다. 프롬프트 템플릿이 긴 첫머리를 켜는 힘의 큰 몫이 이 두 토큰의 바뀐 embedding에 실려 있습니다. 전부는 아닙니다.

### 5. 출력 쪽에서 읽은 것

시작 상태를 층마다 꺼내, 그 층까지의 계산으로는 긴 첫머리(Okay)와 학습 전 모델의 첫머리(To) 가운데 어느 쪽인지를 읽었습니다. 값은 두 토큰의 logit 차이고 양수이면 Okay 쪽입니다. 중간 층의 값은 마지막 층의 읽는 방법을 빌려 쓴 어림입니다.

| 모델 | 입력 | 20층 | 22층 | 24층 | 마지막 |
|---|---|---:|---:|---:|---:|
| 표준 SFT | 표준 | −3.9 | +3.1 | +14.8 | +15.0 |
| A1 | 표준 | −7.9 | −6.2 | +2.9 | +4.2 |
| A2 | 표준 | −9.8 | −14.2 | −12.4 | −10.1 |
| QFFT | 표준 | −8.5 | −11.9 | −11.2 | −16.5 |

- 표준 SFT도 20층까지는 To 쪽이고 22–24층에서 Okay 쪽으로 넘어갑니다. A1과 학습 입력이 같은 A2는 시스템 프롬프트가 있어도 이 층들에서 오르지 않습니다.
- To로 시작하는 모델에도 긴 첫머리는 밑에 남아 있습니다. 첫 토큰으로 Okay가 나올 확률은 A2(표준 입력)에서 학습 전 모델의 92,000배, QFFT에서 152배입니다. 다만 A2에서도 0.004%라 출력되지는 않습니다. A2는 시스템 프롬프트가 있으면 이 확률이 670배 오릅니다. 시스템 프롬프트에 반응하는 것은 남아 있고, 첫 토큰으로 드러나지 않을 뿐입니다.

### 지금 만드는 지도

| 지도 | 무엇을 보이는가 |
|---|---|
| 부분 × 층 지도 | 입력의 각 부분(시스템 프롬프트 문장, 템플릿 토큰, 문제 글, 답이 시작되는 자리)과 각 층에서, 파인튜닝 모델의 상태가 학습 전 모델과 얼마나 달라지는가 |

| 실험 | 결과 | 뜻 |

## 원인이 있을 수 있는 곳

**표 읽는 법.** 왼쪽은 원인이 있을 수 있는 자리, 가운데는 그것을 확인하는 방법, 오른쪽은 지금 상태입니다.

| 후보 지점 | 확인 방법 | 상태 |
|---|---|---|
| 정규화 층의 gain | 모델끼리 가중치 견주기 | 후보에서 뺌(여섯 모델 모두 0.00% 변화) |
| 파인튜닝이 바꾼 가중치의 위치(층, 모듈) | 가중치 차이 지도, 층 구간 바꿔 끼우기 | 한 곳에 모여 있지 않음(모든 층에 나뉘어 있음) |
| 프롬프트 템플릿 토큰의 입력 embedding | 그 행만 학습 전 값으로 되돌리기 | 일부가 여기 있음(0.52 → 0.19) |
| 시작 위치의 방향 하나 | 더하고 빼기 | 11월에 함(켜기에는 충분, 끄기에는 부족) |
| 마지막 층들의 읽기 | 층별로 출력 쪽을 읽음 | 21–24층에서 출력으로 바뀜 |
| 모델 사이의 쓰기와 읽기 | 한 모델의 시작 상태를 다른 모델에 옮겨 심기 | 14층까지 신호가 만들어지고 14–22층에서 다시 읽음 |
| attention head, MLP 층 | 부품 하나의 출력만 바꿔 넣기 | 지도를 만드는 중 |
| 시작 위치가 아닌 다른 위치의 상태 | 부분 × 층 지도, 읽는 자리 지도 | 지도를 만드는 중 |
| 풀이 도중의 전환(wait가 나오는 자리) | 풀이를 따라가며 재기 | 다음 단계 |

## 선행 연구와의 관계

내부 상태를 모델 사이에 바꿔 넣어 원인 지점을 찾는 방법은 이미 여러 연구에 있습니다. 이 글은 그 방법을 새로 제안하지 않고 도구로 씁니다.

| 연구 | 한 일 | 이 글과 다른 점 |
|---|---|---|
| KV-Cache Patching (arXiv 2610.41480) | 파인튜닝 모델과 학습 전 모델 사이에 프롬프트 쪽 계산 결과를 바꿔 넣어, 달라진 행동이 프롬프트를 읽는 쪽에서 오는지 생성하는 쪽에서 오는지 가름 | 학습 전 모델 대 파인튜닝 모델의 비교입니다. 같은 자료로 학습 입력만 다르게 한 형제 모델끼리는 견주지 않습니다 |
| The persona hierarchy model (arXiv 2610.09384) | 학습 때의 시스템 프롬프트를 바꿔 가며 여러 모델을 학습하고, 프롬프트 위치의 상태를 바꿔 넣음 | 긴 풀이와 적응형 추론을 다루지 않습니다 |
| The Thinking Leakage in RL for LLMs (arXiv 2610.14270) | 생각 모드의 전환에 관여하는 attention head를 찾고, 모델 사이에 head를 바꿔 넣음 | 강화학습 모델의 생각 모드 전환입니다. 시스템 프롬프트와 SFT 변형은 다루지 않습니다 |
| Base Models Know How to Reason, Thinking Models Learn When (arXiv 2510.07364) | 학습 전 모델에 방향을 넣어 생각하는 모델의 성능을 되찾음 | 학습 전 모델에 생각을 켜는 방향입니다. 이 글은 긴 풀이만 배운 모델이 스스로 어느 쪽으로 푸는지를 정하는 원인을 찾습니다 |
| ThinkEdit (arXiv 2503.22048) | 풀이 길이를 정하는 방향과 head를 찾아 가중치를 고침 | 지나치게 짧은 풀이를 늘리는 방법입니다. 학습 입력 형식이나 시스템 프롬프트는 다루지 않습니다 |

QFFT 논문과 그것을 인용한 논문 가운데 확인한 범위에서는 모델 안을 분석한 것을 찾지 못했습니다(인용 논문 27편 가운데 3편만 열어 봤습니다). 찾지 못했다는 것이 없다는 보장은 아닙니다.
