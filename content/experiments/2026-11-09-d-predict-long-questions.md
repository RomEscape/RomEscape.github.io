## 한 줄 요약

앞선 [전체 점검](2026-11-09-a-diagnosis.html)에서 전체 500문제 중 12%가 토큰의 절반을 쓴다는 것을 봤습니다. 이 문제들을 **답을 뽑기 전에** 알아내서 짧은 답을 내는 모델로 보내면 토큰을 크게 줄일 수 있을까요? 결과는 **어느 정도 가려낼 수는 있지만 얻는 것보다 잃는 것이 더 커서, 미리 정한 기준을 넘지 못했습니다.** 길어진 답을 중간에 잘라 내는 단순한 규칙보다도 낫지 않았습니다.

대신 새로 알게 된 것이 있습니다. **항상 긴 문제의 토큰이 전부 낭비는 아닙니다.** 일부 문제는 긴 답이어야만 풀립니다.

## 왜 궁금했나

풀이를 길게 하는 모델은 일부 문제에서 수만 토큰을 씁니다. 그 문제들을 미리 안다면 처음부터 짧은 답을 내는 모델에 맡겨 토큰을 아낄 수 있습니다. 사후에 "항상 긴 문제"를 안다고 가정한 계산에서는 토큰이 0.53배까지 줄어듭니다. 그런데 이 값은 정답을 미리 본 상한입니다. 실제로 답을 뽑기 전에 얼마나 가려낼 수 있는지는 재 봐야 압니다.

## 용어 풀이

| 용어 | 쉬운 뜻 | 이 글에서의 값 |
|---|---|---|
| 토큰 | 글을 나눈 작은 단위. 모델의 작업량을 재는 단위 | 평균 답 4,587토큰 |
| A2, QFFT | 문제를 지우고 긴 풀이만으로 학습한 수학 모델들 | 정답률 약 80% |
| Base | 그런 학습을 하지 않은 원래 모델. 답이 짧다 | 정답률 75.4%, 평균 635토큰 |
| 항상 긴 문제 | 같은 문제에서 16번 답을 뽑았을 때 12번 이상 8,000토큰을 넘는 문제 | A2 61개, QFFT 56개 |
| 판별기 | 문제 글과 Base 답을 보고 "항상 긴 문제일 확률"을 점수로 내는 작은 통계 모델 | 로지스틱 회귀 |
| AUC | 항상 긴 문제 하나, 아닌 문제 하나를 뽑았을 때 판별기가 항상 긴 문제에 더 높은 점수를 줄 확률. 0.5는 동전 던지기, 1은 완벽 | 0.75–0.88 |
| 정밀도 | 항상 길다고 고른 문제 중 실제로 항상 긴 비율 | 0.34–0.56 |
| 재현율 | 실제 항상 긴 문제 중 골라낸 비율 | 0.36–0.59 |
| 상한 규칙 | 답이 일정 토큰을 넘으면 끊고 Base 답으로 대신하는 규칙 | 12,000토큰 기준 토큰 0.75배 |
| 토큰 비 | 정책 적용 후 평균 토큰 ÷ 원래 평균 토큰. 1보다 작으면 아낀 것 | 0.64배 |
| %p | 퍼센트 값의 차이. 80.3%가 79.0%가 되면 −1.3%p | |

## 어떻게 했나

새로 답을 만들지 않고, 저장되어 있는 수학 500문제의 답(모델당 문제별 16번)으로 계산했습니다.

1. **답을 알려 주는 표지를 정합니다.** 각 문제가 항상 긴 문제인지, 그 모델의 16번 답으로 정합니다.
2. **판별기에 넣을 재료를 만듭니다.** 문제 글에서 글자 수, 낱말 수, 숫자 수, 수식 명령 수, 그림 유무, "how many" 같은 낱말의 유무를 셉니다. 여기에 Base 답 1개의 길이와 답을 냈는지 여부를 더합니다. 이 묶음을 **주 재료**로 미리 정했습니다.
3. **문제를 5묶음으로 나눕니다.** 4묶음으로 판별기를 학습하고 나머지 1묶음을 점수 냅니다. 묶음을 돌아가며 반복하므로, 어떤 문제의 점수도 그 문제의 답을 본 판별기에서 나오지 않습니다.
4. **어디서 자를지 정합니다.** 학습 묶음의 항상 긴 문제 비율(약 12%)만큼 높은 점수를 "보낸다"로 정합니다.
5. **기대 정답률과 토큰을 계산합니다.** 보낸 문제는 Base 답을 씁니다. 안 보낸 문제는 모델 답을 쓰되 12,000토큰을 넘으면 Base 답으로 대신합니다. 판별에 쓴 Base 답의 토큰은 **모든 문제에** 더했습니다.

**결과를 보기 전에 정한 기준.** A2와 QFFT 모두, 원래보다 정답률이 0.5%p보다 많이 떨어지지 않고(95% 범위 하한도 −2%p 이상), 토큰 비가 12,000토큰 상한 규칙보다 0.05 이상 낮아야(약 0.70배 이하) 후보로 올립니다.

**문제 입력.** 모델에게는 다음과 같은 프롬프트에 문제 글이 들어갑니다. 정답은 저장된 16번 답을 채점할 때만 썼고, 판별기는 보지 않습니다.

```text
system: Please reason step by step, and put your final answer within \boxed{}.
user: <문제 글>
```

**문제 q110: 맞게 가려낸 경우.**

```text
A strictly increasing sequence of positive integers a_1, a_2, a_3, ... has the property that for every
positive integer k, the subsequence a_{2k-1}, a_{2k}, a_{2k+1} is geometric and the subsequence
a_{2k}, a_{2k+1}, a_{2k+2} is arithmetic. Suppose that a_13 = 2016. Find a_1.   (정답 504)
```

- 재료: 306글자, 42낱말, 숫자 16개. Base 답 1개가 32,000토큰까지 이어지고도 답을 내지 못했습니다.
- 판별기 점수 0.99 → 보냄.
- A2 답 16번의 길이는 13,855–32,000토큰으로 16번 모두 8,000을 넘습니다. 맞힌 답은 0개입니다.
- Base는 0%입니다. 보내도 잃는 것이 없고, 토큰만 평균 23,772에서 3,236으로 줍니다.

**문제 q301: 잘못 가려낸 경우.** 우표 가격 표가 든 1,733글자짜리 문제입니다(정답 5.4센트).

- 재료: 글이 길고 숫자가 213개, 그림 있음. Base 답은 463토큰으로 짧습니다.
- 판별기 점수 0.79 → 보냄.
- 실제 A2 답은 16번 중 1번만 8,000토큰을 넘습니다. 이 문제는 항상 긴 문제가 아닙니다.
- 이 문제에서는 Base가 93.8%, A2가 62.5%라 보내도 손해가 없었습니다. 다만 잘못 보낸 문제 전체로 보면 정답률을 잃습니다(아래 표).

**문제 q21: 놓친 경우.**

```text
Find the greatest integer less than (sqrt(7) + sqrt(5))^6.  (Do not use a calculator!)   (정답 13535)
```

- 재료: 90글자, 14낱말, 숫자 3개. Base 답은 615토큰(13823, 오답).
- 판별기 점수 0.001 → 안 보냄.
- 실제로는 16번 모두 8,000토큰을 넘습니다(8,211–32,000).
- 그런데 A2 정답률이 75%이고 Base는 18.8%입니다. **보내지 않아서 다행인 문제입니다.** 짧은 글이 긴 풀이를 요구하는 경우입니다.

## 결과

|---|---|---|---|---|
| A2 | 80.3%, 4,587 | −0.31%p, 0.750배 | −1.30%p [−2.30, −0.36], 0.643배 | 실패(정답률) |
| QFFT | 80.3%, 4,630 | +0.42%p, 0.748배 | −0.53%p [−1.55, +0.44], 0.675배 | 실패(정답률, 0.03%p 차이) |

대괄호는 문제를 다시 뽑아 구한 95% 범위입니다. QFFT는 기준에 아주 가깝지만, 미리 정한 값을 결과를 보고 바꾸지 않습니다. 그래서 다른 학습 자료로 만든 모델에서 재확인하는 다음 단계로 가지 않습니다.

**얼마나 가려낼 수 있었나.** 재료를 바꿔 가며 계산했습니다. 표의 숫자가 클수록 좋습니다.

| 문제 글만 | 0.760 | 0.748 | 0.563 / 0.598 |

Base 답을 많이 보면 판별은 좋아지지만, 그 답을 모든 문제에 대해 만드는 비용이 커서 토큰이 오히려 늘어납니다. 난도와 분야는 실제 사용 때 주어지지 않는 정보라 참고로만 넣었습니다.

**왜 실패했나.** A2에서 주 재료로 보낸 67문제를 나눠 봤습니다.

| 경우 | 문제 수 | 모델 정답률 | Base 정답률 | 모델 평균 토큰 | Base 평균 토큰 |
|---|---:|---:|---:|---:|---:|
| 맞게 보냄 (항상 긴 문제) | 30 | 17.3% | 13.1% | 19,320 | 1,180 |
| 잘못 보냄 (길이가 들쭉날쭉한 문제) | 13 | 58.2% | 43.8% | 10,145 | 1,128 |

보낸 문제의 절반 이상이 잘못 보낸 것입니다. 그 문제들은 Base로 가면서 14%p, 10%p씩 정답률을 잃습니다. 아낀 토큰보다 이 손실이 큽니다. 또 항상 긴 문제의 절반은 잡지 못해 토큰을 그대로 씁니다.

**단순 규칙과의 비교(결과를 본 뒤 추가).** [앞 글](2026-11-09-b-cut-long-answers.html)의 상한 규칙은 답 도중에 잘라 내는 방식입니다. 8,000토큰 상한은 A2에서 −0.81%p에 0.62배, QFFT에서 −0.39%p에 0.625배입니다. 같은 정답률 손실에서 비교하면 주 재료의 토큰 비(A2 0.643, QFFT 0.675)가 상한 규칙(A2 0.542, QFFT 0.606)보다 나쁩니다. 답을 뽑기 전에 판단하는 것보다 답이 길어지는 것을 보고 판단하는 쪽이 낫습니다.

## 새로 알게 된 것: 항상 긴 문제 안에서도 값이 갈립니다

항상 긴 문제의 16번 정답률을 모델과 Base로 나눠 봤습니다. 이 분류는 결과를 본 뒤 나눈 것입니다.

| 모델 | 항상 긴 문제 | 둘 다 25% 미만 (그 문제들이 쓴 토큰의 몫) | 모델이 Base보다 25%p 이상 높음 (토큰 몫) | Base가 25%p 이상 높음 |
|---|---:|---:|---:|---:|
| A2 | 61개 | 30개 (53.8%) | 14개 (20.4%) | 7개 |
| QFFT | 56개 | 32개 (62.2%) | 8개 (11.4%) | 6개 |

실제 문제로 보면 다음과 같습니다.

- **긴 답이 값을 내는 문제 q371.** `|ax^2 + bx + c| ≤ 1`이 `0 ≤ x ≤ 1`에서 성립할 때 `|a| + |b| + |c|`의 최댓값을 묻습니다(정답 17). A2 답 16번 중 14번이 8,000토큰을 넘고 평균 14,278토큰인데 정답률이 81.3%입니다. Base는 0%입니다.
- **값 없이 토큰을 쓰는 문제 q110.** 평균 23,772토큰, A2 0%, Base 0%입니다.
- **길어져서 오히려 잃는 문제 q324.** 원의 넓이를 묻는 문제로 A2가 16번 모두 길고 18.8%입니다. Base는 62.5%입니다.

**값을 완벽히 안다면 얼마나 줄일 수 있을까(11월 9일 추가).** 항상 긴 문제마다 모델과 Base 중 어느 쪽이 더 잘 맞히는지 미리 안다고 치고 계산했습니다. 고를 때 쓴 답으로 채점하면 점수가 부풀기 때문에, 16번 중 앞 8번으로 고르고 뒤 8번으로 평가했고 반대 방향도 한 번 더 했습니다. A2와 QFFT 두 모델이니 모두 네 번 잰 범위입니다.

| 방법 | 정답률 변화 | 토큰 비 |
|---|---:|---:|
| 12,000토큰을 넘으면 끊고 Base로 대체(앞 실험의 단순 규칙) | −0.3–+0.4%p | 0.75배 |
| 항상 긴 문제에서 더 잘 맞히는 쪽을 안다고 치기 | +0.1–+0.4%p | 0.69–0.72배 |
| 항상 긴 문제는 아는 쪽으로, 나머지 문제는 끊기(결과를 보고 더한 계산) | +0.2–+0.5%p | 0.63–0.65배 |

실제 예로 앞의 q371은 A2가 81.3%이고 Base가 0%라 모델 쪽으로 보내고, q324는 A2가 18.8%이고 Base가 62.5%라 Base 쪽으로 보냅니다.

계산 전에 정한 기준은 "더 잘 맞히는 쪽을 안다고 칠 때 토큰이 0.65배 이하"였고 넘지 못했습니다(0.69–0.72배). 세 번째 줄은 기준을 정한 뒤에 추가로 계산한 값이라 판정에 쓰지 않았습니다. 이 표는 미리 알 수 없는 정답 정보를 그대로 쓴 천장입니다. 실제로 가려내는 판별기는 틀리는 만큼 이보다 덜 줄어듭니다.

## 표 읽는 법

토큰 비가 작을수록 많이 아낀 것이고, 정답률 차가 0에 가까울수록 잘 지킨 것입니다. 두 숫자는 함께 봐야 합니다. 토큰을 많이 아껴도 정답률을 크게 잃으면 쓸 수 없습니다.

## 그래서 무슨 뜻인가

- 항상 긴 문제는 문제 글과 짧은 답에서 어느 정도 드러납니다(AUC 0.75–0.83). 그러나 문제 단위로 보내는 결정은 틀렸을 때 손해가 커서 쓸 만한 수준이 아닙니다.
- 지금 있는 재료로는 "답을 보기 전에 가르기"가 "길어지는 것을 보고 끊기"를 넘지 못합니다.
- 긴 답의 값은 문제마다 다릅니다. 길이만 보는 규칙은 q371 같은 문제까지 잘라 냅니다. 앞으로는 "길이"가 아니라 "그 토큰이 값을 내는가"를 잴 방법이 필요합니다.
- 다만 문제별 값을 완벽히 안다고 쳐도 토큰은 0.69–0.72배까지만 줄어, 길면 끊는 단순 규칙(0.75배)과 크게 다르지 않습니다. 그래서 값을 미리 가리는 일을 새 방법으로 밀지 않고, 긴 답이 왜 생기는지 설명하는 재료로 둡니다.

## 다른 연구와 겹치는가

질문을 비싼 모델과 저렴한 모델로 나눠 보내는 방식은 이미 [RouteLLM](https://arxiv.org/abs/2406.18665) 등에서 연구됐고, 추론 모델에서 긴 추론과 짧은 추론을 고르는 방법도 [Thinkless](https://arxiv.org/abs/2505.13379) 같은 연구가 있습니다. 그래서 이 글의 내용을 새 방법으로 내세우지 않습니다. 재는 값으로만 씁니다.

## 한계

- 수학 500문제에서 교차로 계산한 값이고, 실제로 답을 다시 생성해 확인하지 않았습니다.
- 판별기는 단순한 통계 모델입니다. 더 복잡한 모델이나 문제의 내부 표현을 쓰면 달라질 수 있습니다. 이번에는 내부 표현을 저장한 파일을 쓰지 못했습니다.
- 값이 갈린다는 표는 정답을 본 뒤 나눈 것이라 인과가 아닙니다. 정답을 모르는 상태에서 나눌 수 있는지는 아직 재지 않았습니다.
- 특징으로 쓴 낱말 목록과 정책의 재료는 제가 정했습니다.
