## 연구 질문

| 순서 | 내용 |
|---|---|
| 본 현상 | 표준 SFT는 시스템 프롬프트를 뜻이 같은 다른 문장으로 바꿔도 길게 풀었고(0.81배), 모델 안의 상태에 "시스템 프롬프트가 있을 때의 방향"을 더하면 답이 "Okay"로 시작했습니다. 다만 답의 앞 2,048 tokens까지만 본 결과였습니다. |
| 든 의문 | 문장의 한 구절만 바꿔 쉬운 문제는 짧게, 어려운 문제는 길게 풀게 할 수 있는가? 답이 시작되는 자리 한 곳의 상태만 바꿔도 긴 풀이가 돌아오는가? 시스템 프롬프트는 답을 시작할 때 한 번만 쓰이는가, 풀이 내내 쓰이는가? |
| 그때까지 안 해 본 것 | 문장의 한 구절만 바꾸기, 답을 끝까지 생성하면서 방향 더하기, 풀이 도중에 시스템 프롬프트 바꾸기는 해 본 적이 없었습니다. 실험 전에 관련 논문을 다시 읽고 이미 나온 방법과 겹치지 않는 부분을 골랐습니다. |
| 그래서 한 것 | 시스템 프롬프트의 "reason step by step"을 "answer concisely"로 바꿨습니다. 모델 안의 방향을 답이 시작되는 자리 한 곳에만 더했습니다. 풀이를 1,024 tokens까지 써 둔 뒤에 시스템 프롬프트를 뺐습니다. 모두 답을 끝까지(최대 32,000 tokens) 생성했습니다. |
| 답 | "answer concisely"로 바꾸면 쉬운 문제(GSM8K)의 답은 0.49배로 줄고 어려운 문제(AIME25)의 답은 0.97배로 그대로였습니다. MATH500 정답률은 같았습니다. 방향을 한 곳에만 더해도 긴 풀이가 거의 돌아왔습니다. 풀이 도중에 시스템 프롬프트를 빼면 그 뒤에 이어 쓰는 길이가 21%(표준 SFT), 27%(A1) 줄었습니다. |
| 다음 의문 | 이 배분은 표준 SFT에서만 나오는가? 모델은 문장의 글자에 반응하는가, 뜻에 반응하는가? 그 방향은 모델의 어느 층에서 작동하고 학습 전 모델에도 있는가? ([묶음 2](2026-11-19-a-system-prompt-batch2.html)) |

질문의 사슬 전체는 [연구 질문으로 다시 쓴 QFFT 연구](2026-11-25-a-research-questions.html)에 있습니다.

## 메인 표: Base, SFT, A1, A2, QFFT와 추론 입력을 바꾼 조건

**표 읽는 법.** 한 줄이 "모델 + 추론 입력" 하나입니다. ACC는 정답률(%), Tokens는 답 하나의 평균 출력 tokens입니다. "구분"이 줄의 뜻입니다. 기준은 학습 방법이 다른 모델들을 표준 평가 그대로 잰 값이고, 굵게 적은 A2와 QFFT가 견줄 상대입니다. 방법은 표준 SFT를 다시 학습하지 않고 추론 입력만 바꾼 값입니다. 참고는 같은 입력 변경을 다른 모델에 얹어 본 값입니다. "대기"는 지금 돌고 있는 칸입니다.

| 구분 | 모델 | 추론 입력 | GSM8K ACC | GSM8K Tokens | MATH500 ACC | MATH500 Tokens | AIME25 ACC | AIME25 Tokens |
|---|---|---|---|---|---|---|---|---|
| 기준 | Base | 기본 프롬프트 | 92.0 | 301 | 76.1 | 635 | 8.8 | 1,060 |
| 기준 | SFT | 기본 프롬프트 | 91.6 | 2,060 | 81.0 | 6,576 | 16.7 | 20,574 |
| 기준 | A1 | 기본 프롬프트 | 91.4 | 1,856 | 80.9 | 6,149 | 17.5 | 18,965 |
| 기준 | **A2** | 기본 프롬프트 | **91.6** | **888** | **81.3** | **4,587** | **17.5** | **17,735** |
| 기준 | **QFFT** | 기본 프롬프트 | **92.0** | **831** | **81.4** | **4,630** | **15.4** | **18,133** |
| 방법 (SysDrop) | SFT | 시스템 프롬프트 제거 | 91.0 | 1,517 | 80.9 | 4,899 | 19.2 | 18,382 |
| 방법 (CueDrop) | SFT | 문제 글만 | 대기 | 대기 | 81.4 | 4,221 | 대기 | 대기 |
| 참고 | A1 | 시스템 프롬프트 제거 | 91.5 | 587 | 81.6 | 3,778 | 12.5 | 16,270 |
| 참고 | A2 | 시스템 프롬프트 제거 | 91.6 | 514 | 82.0 | 3,948 | 값 없음 | 값 없음 |
| 참고 | QFFT | 시스템 프롬프트 제거 | 91.3 | 630 | 82.5 | 4,122 | 값 없음 | 값 없음 |
| 참고 | QFFT | 문제 글만 | 대기 | 대기 | 77.5 | 5,046 | 대기 | 대기 |

- **모델.** Base는 파인튜닝 전의 Qwen2.5-7B-Instruct입니다. 나머지는 모두 LIMO 817문항으로 학습했습니다. SFT는 QFFT 논문이 비교 기준으로 쓴 표준 SFT로, 시스템 프롬프트와 질문, 긴 풀이를 그대로 학습한 모델입니다. A1은 질문을 지우고, A2는 질문을 지우고 응답 첫 토큰의 loss까지 빼고, QFFT는 논문 방법대로 질문 없이 풀이만으로 학습한 모델입니다.
- **무엇을 견주는가.** A2와 QFFT는 학습 방법을 바꿔 새로 학습한 모델입니다. 방법 줄은 표준 SFT의 가중치를 그대로 두고 추론 입력만 바꾼 것입니다. A2나 QFFT 위에 얹은 것이 아니라, A2, QFFT와 나란히 견주는 다른 길입니다. 같은 입력 변경을 A1, A2, QFFT에 얹어 본 값은 참고 줄에 따로 두었습니다.
- **추론 입력.** 기본 프롬프트는 대화 틀, 시스템 프롬프트 "Please reason step by step, and put your final answer within \boxed{}.", 질문으로 이루어집니다. 시스템 프롬프트 제거는 거기서 시스템 프롬프트만 뺀 입력이고, 문제 글만은 대화 틀까지 빼고 질문 글자만 준 입력입니다. 실제 문자열은 아래 "실제 입력과 실제 답"에 있습니다.
- **크기.** GSM8K 1,319문항, MATH500 500문항, AIME25 30문항입니다. 기본 프롬프트 줄은 문항마다 16회, 나머지 줄은 4회 풀게 했습니다. 최대 32,000 tokens입니다.
- **채점.** GSM8K와 MATH500의 ACC는 `\boxed{}` 없이 끝난 답을 직접 읽어 반영하고, 표기만 다른 같은 답을 맞게 고친 값입니다(GSM8K는 평가 자료의 정답 16문항도 바로잡았습니다). AIME25는 공식 채점 스크립트 값 그대로입니다.
- **읽기.** MATH500에서 표준 SFT에 문제 글만 준 줄(CueDrop)은 ACC 81.4%, 4,221 tokens입니다. A2(81.3%, 4,587)와 QFFT(81.4%, 4,630)와 정답률이 같고 8–9% 짧습니다. GSM8K와 AIME25의 같은 칸은 아직 돌지 않았습니다. 참고 줄을 보면 A2와 QFFT도 시스템 프롬프트를 빼면 더 짧아집니다(3,948, 4,122 tokens).

11월 15일 글에서 "SFT가 길게 푸는 것은 시스템 프롬프트의 뜻에 반응한다"를 작게 확인했습니다. 이번에는 관련 논문을 다시 읽고, 지금 바로 돌릴 수 있는 실험 세 개를 끝까지(최대 32,000 tokens) 돌렸습니다.

1. **문제 맞춤 프롬프트.** 기본 문장 "Please reason step by step, and put your final answer within \boxed{}."에서 "reason step by step"을 "answer concisely"로 바꾸기만 했습니다. 그러자 쉬운 문제는 크게 짧아지고(GSM8K 0.49배), 어려운 문제는 그대로 길게 풀었습니다(AIME25 0.97배). MATH500 정답률은 같았습니다. 반대로 은닉 상태나 난이도 같은 신호로 문제마다 문장을 골라 주는 방법은 무작위로 고르는 것보다 낫지 않았습니다. 문장 하나만 바꿔도 모델이 스스로 배분하기 때문입니다.
2. **응답 시작 상태.** 시스템 프롬프트가 있을 때와 없을 때의 내부 상태 차이(방향 v)를, 응답이 시작되는 위치 한 곳에만 더했습니다. 그러자 긴 풀이가 기본 프롬프트 수준 가까이 돌아왔고, 답 형식과 정답률도 유지됐습니다. 같은 방향을 생성 내내 더하면 답 형식이 깨지고, 더 크게 더하면 글이 무너졌습니다. 같은 크기의 무작위 방향도 생성 내내 더하면 무너졌습니다.
3. **풀이 도중 교체.** 같은 풀이를 1,024 tokens까지 써 둔 뒤에 시스템 프롬프트를 빼도, 이어 쓰는 길이가 21%(SFT), 27%(질문 제거 SFT) 줄었습니다. 시스템 프롬프트는 응답을 시작할 때 한 번만 작용하는 것이 아니라 풀이 내내 다시 읽힙니다.

정리하면 이렇습니다. 시스템 프롬프트의 길이 효과는 대부분 응답 시작 상태가 정하고, 풀이 도중에도 시스템 프롬프트를 계속 참조하는 몫이 남습니다.

## 왜 궁금했나

교수님께서 11월 12일 결과에 대해 "시스템 프롬프트를 빼서 잘됐다가 아니라, 모델이 추론을 시작하는 상태에 따라 변한다로 일반화해야 한다"고 지적하셨습니다. 또 "프롬프트 대신 벡터로도 되는지", "어려운 문제에서 배분이 되는지"도 보라고 하셨습니다.

11월 17일에는 "시스템 프롬프트 관련 논문을 다시 읽고, 지금 가능한 추가 실험이나 확장 실험, 아니면 문제에 맞게 프롬프트를 바꿔 적용해 보기"를 요청받았습니다. 그래서 논문을 세 갈래로 다시 읽고(아래 "선행 연구와의 관계"), 겹치지 않는 부분을 골랐습니다.

- 문제에 맞게 시스템 프롬프트를 바꾸면 쉬운 문제는 짧게, 어려운 문제는 길게 풀까? 바꾸는 방법은 두 가지로 봤습니다. 문장 자체를 바꾸는 방법과, 문제마다 다른 문장을 골라 주는 방법입니다.
- 11월 15일에 2,048 tokens까지만 본 "방향을 더하면 Okay로 시작한다"가 끝까지 생성해도 기본 프롬프트를 대신하는가? 응답 시작 위치 한 곳만으로도 되는가?
- 시스템 프롬프트는 풀이 앞부분에서 한 번 작용하는가, 풀이 내내 읽히는가? 이 실험은 11월 10일에 설계와 작은 시험까지 하고 본 실행만 남아 있었습니다.

시스템 프롬프트를 통째로 빼거나 문장 일부를 빼는 실험, 같은 뜻이나 무관한 문장으로 바꾸는 실험은 이미 했으므로 다시 돌리지 않고 저장된 결과를 기준으로 썼습니다.

### 문항 하나로 따라가 보기 (문장 바꾸기와 방향 더하기)

MATH500의 Level 1 문항입니다. 조건마다 첫 번째 답을 실었습니다. 이 문항은 규칙으로 골랐습니다(방향 실험의 100문항 가운데 Level 1이고, 기본과 간결 문장 모두 `\boxed{}`로 답했으며, 두 길이의 차이가 가장 큰 문항).

> What is the difference between the positive square root of 64 and the cube root of 64? (정답 4)

| 조건 | 응답의 첫머리 | 길이 (tokens) | 끝 |
|---|---|---|---|
| 기본 시스템 프롬프트 | "Okay, so I need to find the difference between the positive square root of 64 and the cube root of 64. Let me break this down step by step." | 1,528 | `\boxed{4}` |
| 시스템 프롬프트 없음 | 위와 같은 첫 문장 | 607 | `\boxed{4}` |
| "Please reason briefly, …" | 위와 같은 첫 문장 | 1,031 | `\boxed{4}` |
| "Please answer concisely, …" | "First, find the positive square root of 64. The square root of 64 is 8, since 8^2 = 64." | **111** | `\boxed{4}` |
| "Judge how hard the problem is. If it is easy, answer briefly; if it is hard, reason step by step. …" | 위의 Okay 첫 문장 | 660 | "Therefore, the problem is an easy one." 뒤 `\boxed{4}` |
| 없음 + 시작 위치에만 v 1배 | 위의 Okay 첫 문장 | 959 | `\boxed{4}` |
| 없음 + 생성 내내 v 0.5배 | 위의 Okay 첫 문장 | 1,842 | 상자 없이 "The difference is 4." |
| 없음 + 생성 내내 v 1배 | "Okay, so I need to find the difference … Let me start by recalling what a square root is." | 2,020 | 상자 없이 "8 − 4 = 4. That seems right."으로 끝남 |

- 간결 문장(answer concisely)만 Okay로 시작하지 않고, 바로 계산해 111 tokens에 끝났습니다.
- 조건부 문장은 "쉬운 문제"라고 스스로 말하면서도 660 tokens를 썼습니다.
- 생성 내내 방향을 더하면 답은 맞게 구하지만 `\boxed{}`에 넣지 않아 자동 채점에서는 오답입니다.

### 어려운 문제에서는 간결하게 하라고 해도 길게 푼다

AIME25 18번 문항(로그가 들어간 곱을 기약분수로 나타내는 문제, 정답 106)에서 "Please answer concisely, …"를 넣은 SFT의 답 하나입니다. 정상 종료하고 `\boxed{}`가 있는 답 가운데 길이가 중앙값에 가장 가까운 것을 골랐습니다.

- 첫머리는 기본 프롬프트처럼 "Okay, so I need to evaluate this product:"로 시작합니다.
- Wait가 107번 나오며 재검토를 거듭하고, 16,533 tokens 뒤에 `\boxed{106}`으로 맞혔습니다.

같은 문장을 넣어도 GSM8K 답의 길이 중앙값은 894 tokens였습니다(예: "Okay, so Erika wants a laptop that costs $600. If she trades in her old one, it's $200 off, …"). 지시는 같은데 문제가 어려울수록 길게 풉니다.

### 풀이 도중 시스템 프롬프트를 바꾸면

SFT에서 미리 생성해 둔 답(첫 토큰을 "To"로 고정해 기본 시스템 프롬프트로 생성)의 앞 1,024 tokens를 그대로 두고, 그 뒤만 다시 생성했습니다. 이어 쓸 때의 입력은 둘 중 하나입니다.

- 기본 시스템 프롬프트 + 질문 + 앞 1,024 tokens
- 시스템 프롬프트 없이 질문 + 같은 앞 1,024 tokens

원형에 내접한 육각형의 각을 구하는 문항(앞부분은 "To solve for the measure of angle α in the inscribed hexagon, I need to use some properties of cyclic hexagons …")에서, 기본으로 이어 쓰면 24,911 tokens, 시스템 프롬프트를 빼고 이어 쓰면 19,803 tokens를 더 썼습니다(0.79배). 이 문항은 SFT의 평균 비(0.79)와 가장 가까운 문항을 골랐습니다. 이미 1,024 tokens를 같게 썼는데도 시스템 프롬프트가 있는지에 따라 남은 길이가 달라졌습니다.

- AIME25에서도 정답률이 오르지 않았습니다. 생성 내내 0.5배는 13.3%로 시스템 프롬프트 없음(19.2%)보다 낮았고, 1배는 0%였습니다.

### 4. 풀이 도중 교체

토큰 비는 앞부분 뒤에 이어 쓴 길이만 비교한 값입니다. "제거"는 기본으로 시작한 풀이를 시스템 프롬프트 없이 이어 쓴 길이 ÷ 기본으로 이어 쓴 길이입니다. "추가"는 그 반대 방향입니다.

| 모델 | 앞부분 길이 | 제거 [95% CI] | 추가 [95% CI] |
|---|---|---|---|
| SFT | 64 | 0.73 [0.64, 0.84] | 1.67 [1.45, 1.98] |
| | 256 | 0.89 [0.76, 1.05] | 1.26 [1.05, 1.49] |
| | 1,024 | 0.79 [0.66, 0.94] | 1.67 [1.25, 2.25] |
| 질문 제거 SFT (A1) | 64 | 0.77 [0.66, 0.91] | 1.26 [1.12, 1.44] |
| | 256 | 0.71 [0.61, 0.83] | 1.24 [1.00, 1.54] |
| | 1,024 | 0.73 [0.56, 0.97] | 1.45 [1.02, 2.11] |

시드만 바꿔 같은 조건을 다시 생성한 비는 SFT 1.06, A1 0.92였습니다. 그러니 위의 차이는 샘플링 편차보다 큽니다.

**표 읽는 법.** SFT의 1,024 행에서 0.79는, 같은 1,024 tokens 앞부분 뒤에서 시스템 프롬프트를 빼면 남은 풀이가 21% 짧아진다는 뜻입니다. 95% CI의 위쪽(0.94)이 1보다 작아 "짧아진다"고 말할 수 있습니다.

- 풀이가 1,024 tokens 진행된 뒤에도 시스템 프롬프트를 빼면 짧아지고 넣으면 길어졌습니다. 시스템 프롬프트는 풀이 내내 읽힙니다.
- SFT와 A1의 차이는 없었습니다. 두 모델 모두 학습 때 같은 시스템 프롬프트를 봤습니다.
- SFT에서 시스템 프롬프트를 빼고 이어 쓰면 정답률이 깊이 64에서 8.0%p, 1,024에서 9.3%p 낮았습니다. `\boxed{}` 비율 차이는 1–4%p뿐이라 형식만의 문제는 아닙니다. 다만 문항마다 한 번씩만 생성해 범위가 넓습니다.

## 이 결과로 말할 수 있는 것과 없는 것

**말할 수 있는 것**

- 학습 없이 시스템 프롬프트 문장 하나만 바꿔도("answer concisely") SFT가 쉬운 문제는 짧게, 어려운 문제는 길게 배분합니다. MATH500 정답률은 같았습니다.
- 학습 때 구절 "reason step by step"이 들어 있으면, 조건을 붙여도 모델은 그 구절에 의존해 길게 풉니다.
- 이 모델에서는 바깥에서 문제마다 문장을 골라 주는 방법(은닉 상태, 난이도, 초안)이 무작위보다 낫지 않았습니다.
- 시스템 프롬프트의 효과는 대부분 응답 시작 위치의 상태로 전달됩니다(그 위치에만 더해도 0.82–0.86배). 그리고 풀이 내내 다시 읽힙니다(1,024 tokens 뒤에 빼도 0.79배).

**아직 말할 수 없는 것**

- 간결 문장이 어려운 문제의 정답률을 지킨다(AIME25는 30문항이라 범위가 ±7%p).
- 간결 문장의 GSM8K 정답률 하락(1.9%p)이 문장 때문이다. 기준 결과는 다른 엔진으로 만든 저장 결과라 엔진 차이가 섞였을 수 있습니다.
- 시작 위치에만 더한 방향이 시스템 프롬프트를 완전히 대신한다(0.82–0.86배, 기준 1에 못 미침).
- 풀이 도중 시스템 프롬프트를 빼면 정답률이 떨어진다(한 번씩만 생성).

## 한계

- 모든 모델은 학습을 한 번씩만 했습니다.
- 이번 생성 엔진(vLLM 0.11)이 기준 결과를 만든 엔진과 다릅니다. 같은 엔진에서 아무것도 더하지 않은 조건은 저장된 결과의 0.89배로 미리 정한 허용 범위 안이었습니다.
- 벡터 실험은 100문항 × 2회라 정답률 범위가 ±6%p 정도입니다.
- 생성 내내 1배 더한 조건과 무작위 방향 조건은 답이 너무 길어져, 생성 엔진이 일부 요청의 앞부분을 다시 계산했습니다. 이때 방향이 빠졌을 수 있지만 결론(붕괴)은 바뀌지 않습니다. 시작 위치에만 더한 조건에서는 이런 일이 없었습니다.
- 풀이 도중 교체의 앞부분은 첫 토큰을 "To"로 고정해 생성한 답입니다. 바꾼 뒤에는 앞부분을 새로 읽혀 이어 썼습니다.
- 계획에 더했던 무작위 방향 두 개(각 100문항 × 1회)는 시간 때문에 돌리지 않았습니다.
