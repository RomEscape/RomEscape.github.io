## 연구 질문과 지금 상황 (11월 25일)

**큰 질문.** 긴 풀이를 배운 모델은 왜 쉬운 문제에도 길게 푸는가, 그리고 QFFT는 무엇을 바꿨기에 그러지 않는가.

**본 현상.** 어려운 수학 문제 817개의 긴 풀이로 SFT한 모델은 쉬운 문제에도 길게 풉니다. MATH500의 가장 쉬운 수준 문항 "2^8 = 4^x에서 x는?"에 파인튜닝 전 모델은 평균 222 tokens를 쓰고 SFT는 886 tokens를 씁니다. 답은 같습니다. QFFT 논문은 학습 자료에서 질문을 지우면 이 길이가 줄어든다고 보고했습니다.

**지금의 답.** 모델은 길게 푸는 방식을, 학습 때 그 풀이와 늘 함께 있던 입력(풀이를 서술하는 지시문)에 의존해 켭니다. 표준 평가는 모든 모델에 같은 지시문을 주는데, 그 지시문은 SFT에게만 학습 때 본 것입니다. 그래서 SFT를 다시 학습하지 않고 추론 입력에서 그 단서만 빼도 A2, QFFT와 같은 정답률에 더 짧게 풉니다(아래 메인 표의 MATH500). 어려운 문제(AIME25)에서 정답률이 지켜지는지, 왜 풀이를 서술하는 지시문에만 의존이 생기는지는 아직 열려 있습니다.

### 메인 표: Base, SFT, A1, A2, QFFT와 추론 입력을 바꾼 조건

**표 읽는 법.** 한 줄이 "모델 + 추론 입력" 하나입니다. ACC는 정답률(%), Tokens는 답 하나의 평균 출력 tokens입니다. "구분"이 줄의 뜻입니다. 기준은 학습 방법이 다른 모델들을 표준 평가 그대로 잰 값이고, 굵게 적은 A2와 QFFT가 견줄 상대입니다. 방법은 표준 SFT를 다시 학습하지 않고 추론 입력만 바꾼 값입니다. 참고는 같은 입력 변경을 다른 모델에 얹어 본 값입니다. "대기"는 지금 돌고 있는 칸입니다.

- **모델.** Base는 파인튜닝 전의 Qwen2.5-7B-Instruct입니다. 나머지는 모두 LIMO 817문항으로 학습했습니다. SFT는 QFFT 논문이 비교 기준으로 쓴 표준 SFT로, 시스템 프롬프트와 질문, 긴 풀이를 그대로 학습한 모델입니다. A1은 질문을 지우고, A2는 질문을 지우고 응답 첫 토큰의 loss까지 빼고, QFFT는 논문 방법대로 질문 없이 풀이만으로 학습한 모델입니다.
- **무엇을 견주는가.** A2와 QFFT는 학습 방법을 바꿔 새로 학습한 모델입니다. 방법 줄은 표준 SFT의 가중치를 그대로 두고 추론 입력만 바꾼 것입니다. A2나 QFFT 위에 얹은 것이 아니라, A2, QFFT와 나란히 견주는 다른 길입니다. 같은 입력 변경을 A1, A2, QFFT에 얹어 본 값은 참고 줄에 따로 두었습니다.
- **추론 입력.** 기본 프롬프트는 대화 틀, 시스템 프롬프트 "Please reason step by step, and put your final answer within \boxed{}.", 질문으로 이루어집니다. 시스템 프롬프트 제거는 거기서 시스템 프롬프트만 뺀 입력이고, 문제 글만은 대화 틀까지 빼고 질문 글자만 준 입력입니다. 실제 문자열은 [연구 질문 정리 글의 "실제 입력과 실제 답"](../experiments/2026-11-25-a-research-questions.html)에 있습니다.
- **크기.** GSM8K 1,319문항, MATH500 500문항, AIME25 30문항입니다. 기본 프롬프트 줄은 문항마다 16회, 나머지 줄은 4회 풀게 했습니다. 최대 32,000 tokens입니다.
- **채점.** GSM8K와 MATH500의 ACC는 `\boxed{}` 없이 끝난 답을 직접 읽어 반영하고, 표기만 다른 같은 답을 맞게 고친 값입니다(GSM8K는 평가 자료의 정답 16문항도 바로잡았습니다). AIME25는 공식 채점 스크립트 값 그대로입니다.
- **읽기.** MATH500에서 표준 SFT에 문제 글만 준 줄(CueDrop)은 ACC 81.4%, 4,221 tokens입니다. A2(81.3%, 4,587)와 QFFT(81.4%, 4,630)와 정답률이 같고 8–9% 짧습니다. GSM8K와 AIME25의 같은 칸은 아직 돌지 않았습니다. 참고 줄을 보면 A2와 QFFT도 시스템 프롬프트를 빼면 더 짧아집니다(3,948, 4,122 tokens).

### 지금 열려 있는 질문

1. 왜 풀이를 서술하는 지시문에만 의존이 생기는가. 뜻이 같고 낱말이 다른 지시문으로 학습해 봐야 가를 수 있습니다(학습 승인 대기).
2. 왜 답을 쓰고도 끝내지 못하는가. 단서를 뺀 입력에서 답의 0.7–7.9%가 답을 쓰고도 같은 줄을 되풀이합니다.
3. 어려운 문제에서 단서가 필요한 때를 모델의 상태로 알 수 있는가. AIME25에서는 단서를 빼면 공개 모델의 정답률이 내려가는 방향입니다.
4. QFFT 학습은 단서를 빼는 것과 무엇이 다른가. 메인 표의 "문제 글만" 줄에서 GSM8K와 AIME25 칸이 채워지면 답할 수 있습니다.
5. 학습을 한 번 더 해도 같은가. 시드만 바꾼 SFT를 학습해 확인합니다.

질문마다의 "본 현상, 든 의문, 그때까지 안 해 본 것, 그래서 한 것, 답, 다음 의문", 모델에 실제로 넣은 입력 문자열과 실제 답, 그리고 실험 글 82편이 이 순서로 진행됐는지의 점검은 [연구 질문으로 다시 쓴 QFFT 연구](../experiments/2026-11-25-a-research-questions.html)에 있습니다.

| 2. 절약 | 목표 정확도를 만족하는 데 필요한 만큼 쓴다 | 필요량을 추정할 수 있는 문항에서 자율 풀이 비용과 필요 추론량을 비교 | 원래 모델이 안정적으로 맞히는 문항에서 A2는 원래 모델의 약 3배를 쓴다 |
| 3. 가치 비례 | 추가 계산으로 정답을 얻을 가능성이 큰 문제와 구간에 토큰을 쓴다 | 문항군별 1,000토큰당 정답률 이득 | 항상 길게 푸는 약 12%의 문항이 토큰의 절반을 쓰고, 그 문항들의 정답률은 20–27%다 |
| 4. 상태 기반 | 오류 가능성이 남으면 풀이를 이어가고 답이 확정되면 마무리한다 | 같은 풀이 앞부분에서 지금 마무리한 답과 더 풀어 얻은 답의 정오, 추가 토큰을 비교 | 반성은 대부분 확인에 그친다(관찰이며 선행 연구와 같은 방향) |
| 5. 형식 불변 | 의미와 요구가 같으면 문체만 바뀌어도 유효한 풀이를 유지한다 | 수학적 조건을 고정하고 문구를 바꿔 풀이 전략, 정답률, 실제 길이를 비교 | SFT는 첫 토큰을 고정해도 시스템 프롬프트를 빼면 답이 0.44배로 짧아진다([기록](../experiments/2026-11-09-h-system-instruction-dependence.html)) |
| 6. 안정성 | 같은 문제를 다시 풀어도 비슷한 양과 결과가 나온다 | 같은 문항 16회의 길이 편차와 정답 일관성 | 16회 중 한 번이라도 맞히는 문항은 96%인데 다수결 정답률은 88%다 |

**어떤 문제에 긴 풀이가 필요한지는 모델과 풀이 방식에 따라 달라집니다.** 기준 모델이 몇 번 맞혔는지는 표본을 나누는 데 쓰고, 실제 판정은 평가하는 모델의 예산별 성능과 비용으로 정합니다.

| 문항군 | 뜻 | 이상적인 행동 |
|---|---|---|
| 짧게 충분 | 적은 비용으로 목표에 도달하고 최고 정답률과의 차이도 허용 범위 안이다 | 짧게 풀고 끝낸다 |
| 추가 추론 필요 | 시험한 조건에서 더 계산해야 두 기준을 모두 충족한다 | 두 기준을 충족하는 가장 저렴한 경로를 택한다 |
| 이득은 있으나 목표 미도달 | 예산을 늘리니 더 많이 맞혔지만 시험한 범위에서는 목표에 못 미친다 | 다른 문제에서 얻을 수 있는 정답 증가와 추가 비용을 함께 비교한다 |
| 미해결 또는 판정 보류 | 모든 예산에서 성능이 낮거나, 표본이 적어 이득이 있는지 가리기 어렵다 | 두 경우를 따로 기록하고 새 전략 또는 추가 측정이 필요한지 판단한다 |

QFFT 논문이 말하는 "짧은 풀이를 먼저 쓰고 필요할 때만 긴 풀이를 쓴다"는 조건 2, 3, 4에 해당합니다. 조건 5(형식 불변)는 이 연구에서 SFT의 긴 풀이가 시스템 프롬프트에 묶여 있는 것을 보고 더한 조건입니다. 11월 8일 설계안의 네 조건(충분성, 절약, 눈금 맞춤, 안정성)에 상태 기반과 형식 불변을 더해 다듬었습니다.

## 용어 풀이

표의 왼쪽은 용어, 가운데는 쉬운 뜻, 오른쪽은 이 글에 나오는 실제 값이나 예입니다.

| 용어 | 뜻 | 이 연구에서의 예 |
|---|---|---|
| 토큰 | 모델이 글을 읽고 쓰는 최소 단위. 영어 단어 하나나 그 일부 정도입니다 | 쉬운 문제에서 Base는 답 하나에 평균 456토큰을 씁니다 |
| 미세조정(학습) | 이미 만들어진 모델에 자료를 더 보여 주어 습관을 바꾸는 일 | 아래 "모델 이름" 표의 모델은 원래 모델(Base)을 빼고 모두 같은 자료(LIMO)로 학습했습니다 |
| 긴 추론(Long CoT) | 혼잣말로 되짚어 보며 길게 쓰는 풀이. "긴 추론 비율"은 QFFT 논문의 공개 코드 규칙대로, 답에 `wait`가 4번 이상 나오거나 `wait`와 `alternatively`가 함께 나오는 답의 비율입니다 | A1 86.0%, A2 39.9% |
| 적응형 추론 | 문제와 풀이 상태에 따라 계산을 배분해 같은 비용으로 더 많이 맞히거나 같은 정확도에 더 적은 비용으로 도달하는 능력 | 남은 두 후보를 가를 수 있는 검사는 하고 이미 해결한 조건의 반복은 줄이기 |
| 라벨 | 학습 자료의 각 자리에서 "여기서는 이 토큰이 와야 맞다"고 알려 주는 정답 | `Wait`가 나오는 자리의 라벨은 `Wait`입니다 |
| 손실 | 모델의 예측이 라벨과 얼마나 다른지를 나타내는 점수. 학습은 이 점수를 줄이는 쪽으로 모델을 고칩니다 | 라벨을 낮은 확률로 예측하면 손실이 큽니다 |
| 라벨 제외 | 그 토큰을 입력으로는 보여 주되 그 자리의 손실만 계산하지 않는 것. 모델은 그 자리에서 그 토큰을 내는 습관을 배우지 않습니다 | 아래 "모델 이름" 표의 A2는 풀이의 첫 토큰을 라벨 제외합니다 |
| 표지(독백 표지) | 풀이 도중 생각의 방향이 바뀔 때 나오는 말 | `Wait`, `Alternatively` |
| 설명체 | `To find ...`처럼 남에게 설명하듯 차례로 써 내려가는 풀이 | A2는 대부분 설명체로 시작합니다 |
| 독백 | `Wait, ...`처럼 혼잣말로 되짚어 보며 쓰는 풀이 | 어려운 문제에서 많이 나옵니다 |
| 체크포인트 | 학습이 끝난 뒤 저장한 모델 파일 | 논문 저자가 공개한 체크포인트 |
| RAK | QFFT 논문의 적응성 점수. 학습 전 모델(Base)이 풀 수 있는 문항이면 짧은 풀이, 못 푸는 문항이면 긴 풀이를 쓰는지가 얼마나 일치하는지를 나타냅니다. 0이면 우연 수준, 100이면 완전 일치입니다 | 아래 "지금까지의 흐름" |
| 매개 | 어떤 원인의 효과가 중간 단계를 거쳐 일어나는 것. "첫 토큰이 매개"는 효과가 첫 토큰의 변화를 거쳐 일어났다는 뜻입니다 | 단축 효과의 약 92% |
| 스모크, 파일럿 | 작은 규모로 먼저 돌려 보는 점검 실험 | 약 190개 |
| 편향 | 내용과 상관없이 한쪽으로 쏠리는 습관 | 겉모습 때문에 습관적으로 길게 쓰는 것 |
| %p(퍼센트포인트) | 퍼센트끼리의 차이 | 86.0%와 39.9%의 차이는 46.1%p |
| 95% 구간 | 문항을 다시 뽑아 계산했을 때 값이 있을 만한 범위. 이 범위가 0을 포함하지 않으면 우연으로 보기 어렵습니다 | 토큰 차이 −1,988의 구간 [−2,189, −1,788] |
| 다수결 | 같은 문제의 여러 답 중 가장 많이 나온 답을 최종 답으로 삼는 것 | 16개 다수결 88% |

## 모델 이름

표 읽는 법: 왼쪽은 모델 이름, 가운데는 학습 방식입니다. 오른쪽 세 숫자는 MATH500에서 잰 결과로, 차례로 정답률, 평균 토큰, 긴 추론 비율입니다. 첫 토큰 라벨 제외가 어떻게 다른지 비교해 보세요.

| 이름 | 학습 방식 | 정답률 · 평균 토큰 · 긴 추론 비율(MATH500) |
|---|---|---|
| Base | 학습 전 Qwen2.5-7B-Instruct | 75.4% · 635 · 0% |
| SFT | 질문과 풀이를 모두 넣고 풀이 전체를 학습 | 79.7% · 6,576 · 91.4% |
| A1 | 질문을 지우고 학습 | 79.7% · 6,149 · 86.0% |
| A2 | 질문을 지우고, 풀이의 첫 토큰도 학습에서 뺌(첫 토큰 라벨 제외) | 80.3% · 4,587 · 39.9% |
| QFFT | 논문의 질문 없는 학습 방법 | 80.3% · 4,630 · 44.1% |

학습 자료는 LIMO(817문항)이며, 어려운 수학 문제 817개와 긴 풀이로 되어 있습니다. 평가는 세 가지 시험 문제 묶음인 MATH500(수학 문제 500개)·GSM8K(초등 수준 서술형 수학 문제 1,319개)·AIME25(미국 수학 경시대회 2025년 문제 30개)에서 문항당 16회 생성으로 했습니다. 16회 생성은 같은 문제를 16번 풀게 한다는 뜻입니다. 모델은 매번 조금씩 다른 답을 씁니다.

## 주요 발견

- **A2는 SFT와 같은 정확도로 훨씬 짧게 풉니다.** MATH500에서 SFT 79.7%·6,576토큰, A2 80.3%·4,587토큰입니다(토큰 차이 −1,988, 95% 구간 [−2,189, −1,788]). 정확도 차이는 0.6%p로 작고, A2가 문제당 평균 1,988토큰을 덜 씁니다. 구간이 전부 0보다 작으므로 A2가 더 짧다는 것은 우연으로 보기 어렵습니다.
- **차이는 쉬운 문제에서 생깁니다.** A2와 SFT 모두 어려운 문제를 더 길게 푸는 순서는 맞습니다. A2는 쉬운 문제를 덜 길게 씁니다. 줄어드는 비율이 쉬운 문제에서 가장 큽니다. 쉬운 문제에서 SFT는 평균 2,792토큰, A2는 1,323토큰을 씁니다([설계안의 문항군별 표](../experiments/2026-11-08-h-design.html)).
- **그래도 쉬운 문제에서는 여전히 토큰을 많이 씁니다.** Base가 안정적으로 맞히는 문항에서 A2는 Base의 약 3배(456 → 1,323토큰)를 씁니다. 다만 그 때문에 정확도가 떨어진다는 것은 확인되지 않았습니다.
- **정확도 여지는 같은 문항 안의 편차에 있습니다.** 16회 중 한 번이라도 맞히는 문항이 96%인데, 16개 다수결은 88%입니다. 같은 문제를 풀 때마다 결과가 달라진다는 뜻입니다. 맞는 풀이를 찾아낼 수는 있지만 매번 그 길로 가지 못합니다.

## 11월 10일에 진행하던 연구

다음 목록은 11월 10일 저녁 기록입니다. 11월 19일 연구 방향은 위의 ‘지금까지의 흐름’에 있습니다.

- **시스템 프롬프트 의존이 첫 토큰 밖에 있는지:** 첫 토큰을 `Okay`와 `Alright`로 강제하고 시스템 프롬프트를 뺐을 때도 SFT만 짧아지는지 봅니다.
- **원인 시험:** 시스템 프롬프트 없이 질문과 풀이로 전체 파인튜닝한 모델(QNOSYS)이 시스템 프롬프트에 묶이지 않는지 봅니다([기록](../experiments/2026-11-09-h-system-instruction-dependence.html)).
- **연쇄 전환 단어 라벨 제외 전체 파인튜닝:** 소규모 LoRA 학습으로는 판정할 수 없었던 방법을 전체 파인튜닝으로 다시 잽니다([기록](../experiments/2026-11-09-e-mask-markers-in-training.html)).
- **학습 데이터 설계:** 첫 토큰을 바꾸는 방법은 선행 연구가 많아 빼고, 형식이 아니라 문제 상태가 긴 추론을 부르게 하는 학습 데이터를 설계 중입니다([설계](../experiments/2026-11-10-a-training-data-design.html)).
